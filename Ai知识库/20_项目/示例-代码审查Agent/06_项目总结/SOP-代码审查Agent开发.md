# SOP: 代码审查Agent开发流程

> **版本**：v1.0
> **状态**：active
> **适用范围**：个人开发代码审查类Agent
> **来源**：从 [[项目经验总结]] 提炼
> **执行时间**：约2天

## 📋 概述

### 目的
标准化代码审查Agent的开发流程，确保：
- 不遗漏关键步骤
- 开发过程可追溯
- 知识可复用
- 质量有保障

### 适用场景
- ✅ 开发新的代码审查Agent
- ✅ 优化现有审查Agent
- ✅ 学习Agent开发方法

### 不适用场景
- ❌ 其他类型的Agent（参考对应SOP）
- ❌ 复杂的多Agent系统

### 预期效果
执行这个SOP后，你能够：
- 系统化地开发审查Agent
- 产出完整的项目文档
- 形成可复用的知识资产
- 在2天内完成基础版本

### 责任人
- 执行人：开发者
- 审核人：自己
- 批准人：自己

## 📝 执行步骤

### 步骤1：需求分析（1.5小时）

#### 目标
明确Agent要解决什么问题

#### 执行动作
- [ ] **1.1 识别痛点**（20分钟）
  - 列出当前代码审查的问题
  - 记录每次审查的痛点
  - 使用 [[模板-技术概念笔记]] 记录

- [ ] **1.2 定义目标**（20分钟）
  - 明确Agent的核心功能
  - 列出验收标准
  - 参考 [[需求文档-代码审查Agent]]

- [ ] **1.3 确定范围**（30分钟）
  - 划分P0/P1/P2功能
  - 明确支持的编程语言
  - 设定时间预期

- [ ] **1.4 查阅知识库**（20分钟）
  - 查看 [[MOC-Agent开发全流程]]
  - 参考类似项目经验
  - 收集最佳实践

#### 判断标准
- [ ] 清晰的问题定义
- [ ] 明确的功能范围
- [ ] 可验证的验收标准

#### 注意事项
- ⚠️ 不要一开始就想做太多
- ⚠️ 专注于核心价值
- ⚠️ 确保在可完成范围内

### 步骤2：Agent设计（2小时）

#### 目标
设计Agent的架构和实现方案

#### 执行动作
- [ ] **2.1 选择Agent类型**（15分钟）
  - 确定使用reviewing Agent

  - 画架构图
  - 定义组件和接口

## ⚠️ 异常处理

### 常见问题

#### 问题1：需求不明确
**现象**：不知道要做什么

**原因**：没有清晰的问题定义

**解决方案**：
1. 先列出当前痛点
2. 从痛点反推需求
3. 参考 [[需求分析方法]]

**预防措施**：
- 一开始就花时间分析问题
- 多问几个为什么

#### 问题2：工具选择困难
**现象**：不知道用什么工具

**原因**：对工具不熟悉

**解决方案**：
1. 参考 [[工具选择决策]]
2. 从简单工具开始
3. 先验证再使用

**预防措施**：
- 提前了解可用工具
- 准备工具清单

#### 问题3：性能不达标
**现象**：处理大文件超时

**原因**：
- 没有考虑大文件情况
- Prompt太长

**解决方案**：
1. 分块处理
2. 优化Prompt
3. 参考 [[问题-工具调用超时]]

**预防措施**：
- 一开始就考虑性能
- 准备大文件测试

#### 问题4：时间超期
**现象**：开发时间超出预期

**原因**：
- 估算过于乐观
- 范围蔓延

**解决方案**：
1. 重新评估优先级
2. 砍掉非核心功能
3. 延长开发时间

**预防措施**：
- 预留20-30% buffer
- 严格的范围控制

### 回退方案
如果开发失败：
1. 保存已完成的代码
2. 记录遇到的问题
3. 总结经验教训
4. 规划下次尝试

### 紧急联系
