# 问题记录：工具调用超时

> **问题ID**：ISSUE-001
> **发现时间**：2026-03-26 10:30
> **解决时间**：2026-03-26 11:15
> **严重程度**：中
> **状态**：✅ 已解决

## 🐛 问题描述

### 现象
在审查较大的Python文件（>200行）时，Agent经常超时：

```
执行检查时超时...
错误：Tool execution timeout
```

### 触发条件
- 文件大小 > 200行
- 代码复杂度较高
- 多个检查规则同时执行

### 影响范围
- 无法审查大文件
- 用户体验差
- 功能受限

---

## 🔍 问题分析

### 根本原因

#### 原因1：单次调用内容过多
```python
# ❌ 问题代码
def check_all_rules(code):
    """一次性检查所有规则"""
    issues = []
    issues += check_naming(code)
    issues += check_imports(code)
    issues += check_docstrings(code)
    issues += check_exceptions(code)
    # ... 更多规则
    return issues
```

**问题**：
- 所有规则在一次调用中执行
- Token消耗大
- 容易超时

#### 原因2：重复分析代码
```python
# ❌ 每个规则都重新解析代码
def check_naming(code):
    lines = code.split('\n')  # 重复操作
    # ...

def check_imports(code):
    lines = code.split('\n')  # 又重复了
    # ...
```

**问题**：
- 每个规则都重新处理代码
- 浪费时间和Token

#### 原因3：Prompt过长
```
System Prompt: ~500 tokens
User Prompt (包含完整代码): ~2000 tokens
多个检查规则: ~1000 tokens
总计: ~3500 tokens
```

**问题**：
- Prompt太长导致处理慢
- 容易超出上下文限制

---

## 💡 解决方案

### 方案1：分块处理（采用）

#### 核心思路
将大文件分成小块，分别检查

```python
def check_large_file(code):
    """分块检查大文件"""
    lines = code.split('\n')

    # 如果文件不大，直接检查
    if len(lines) <= 200:
        return check_all_rules(code)

    # 分块检查
    chunk_size = 100
    issues = []

    for i in range(0, len(lines), chunk_size):
        chunk = '\n'.join(lines[i:i+chunk_size])
        chunk_issues = check_chunk(chunk, i)
        issues.extend(chunk_issues)

    return issues


def check_chunk(chunk, start_line):
    """检查单个代码块"""
    # 只检查这个块内的问题
    issues = []

    # 检查命名（只在当前块）
    issues.extend(check_naming_in_chunk(chunk, start_line))

    # 检查异常处理（需要看上下文）
    issues.extend(check_exceptions_with_context(chunk, start_line))

    return issues
```

**效果**：
- ✅ 每个块处理快
- ✅ 不会超时
- ✅ 定位准确

### 方案2：预分析 + 增量检查（辅助）

#### 核心思路
先快速分析代码结构，再针对性检查

```python
def pre_analyze(code):
    """预分析代码结构"""
    return {
        'functions': find_all_functions(code),
        'classes': find_all_classes(code),
        'imports': find_all_imports(code),
        'lines': len(code.split('\n'))
    }


def incremental_check(code, analysis):
    """基于预分析的增量检查"""
    issues = []

    # 只检查需要检查的部分
    for func in analysis['functions']:
        issues.extend(check_function(func))

    # 只检查导入
    for imp in analysis['imports']:
        issues.extend(check_import(imp))

    return issues
```

**效果**：
- ✅ 避免重复分析
- ✅ 只检查需要的内容
- ✅ 速度提升明显

## 🛠️ 实施过程

### 第1步：实现分块处理（30分钟）

```python
def check_code_in_chunks(code, chunk_size=100):
    """分块检查代码"""
    lines = code.split('\n')

    # 小文件直接检查
    if len(lines) <= chunk_size:
        return check_single_chunk(code, 0)

    # 大文件分块
    all_issues = []
    for i in range(0, len(lines), chunk_size):
        start_line = i
        end_line = min(i + chunk_size, len(lines))
        chunk = '\n'.join(lines[start_line:end_line])

        # 检查这个块
        issues = check_single_chunk(chunk, start_line)
        all_issues.extend(issues)

    return all_issues
```

### 第2步：优化检查规则（20分钟）

```python
# 优化前：每个规则都处理整个代码
def check_naming(code):
    lines = code.split('\n')
    for i, line in enumerate(lines):
        # 检查命名

# 优化后：只处理相关行
def check_naming_in_chunk(chunk, start_line):
    lines = chunk.split('\n')
    issues = []

    for i, line in enumerate(lines):
        # 只检查函数定义行
        if line.strip().startswith('def '):
            if not is_snake_case(extract_function_name(line)):
                issues.append({
                    'line': start_line + i + 1,
                    'rule': 'R001',
                    'message': '函数名应使用snake_case'
                })

    return issues
```

## 📚 经验总结

### 技术经验

1. **分而治之**
   - 大问题拆成小问题
   - 分块处理很有效

2. **预分析很重要**
   - 先了解结构再处理
   - 避免重复工作

3. **Prompt优化**
   - 简洁的Prompt更高效
   - 只包含必要信息

### 方法经验

1. **先定位再解决**
   - 分析根本原因
   - 针对性解决

2. **多方案对比**
   - 不执着于单一方案
   - 选择最合适的

3. **充分测试**
   - 不同大小都要测
   - 确保稳定可靠
