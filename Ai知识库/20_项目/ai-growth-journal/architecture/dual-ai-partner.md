# 双 AI 合伙人架构：Claude Code + OpenClaw

> 创建时间：2026-03-15
> 作者：李志刚

---

## 一、核心理念

**让两个 AI 各司其职，发挥各自优势，形成最佳效能**

---

## 二、角色定位

| 角色 | 工具 | 定位 | 优势 | 局限 |
|------|------|------|------|------|
| **工程合伙人** | Claude Code (CC) | 代码开发、工程管理 | 稳定性、安全性最强 | 无手机端、无随时沟通 |
| **全天候合伙人** | OpenClaw | 24×7 任务助手、AI 合伙人 | 随时随地、手机端、飞书对接 | 工程能力不如 CC |

---

## 三、分工原则

### Claude Code (CC) 负责

| 领域 | 具体内容 |
|------|----------|
| **代码开发** | Python Agent 开发、复杂编程 |
| **工程管理** | 项目架构、代码审查 |
| **安全敏感** | 涉及密钥、敏感数据的操作 |
| **稳定性要求高** | 需要高可靠性的任务 |

### OpenClaw 负责

| 领域 | 具体内容 |
|------|----------|
| **随时沟通** | 飞书、手机端即时响应 |
| **任务协调** | 24×7 值守、任务分发 |
| **知识管理** | 记忆、文档、学习笔记 |
| **团队协作** | 多 Agent 协同 |
| **日常助手** | 信息查询、提醒、整理 |

## 五、迁移机制

### 从 CC 迁移到 OpenClaw

| 步骤 | 内容 |
|------|------|
| 1 | CC 完成代码开发（Python Agent） |
| 2 | 代码提交到 GitHub 仓库 |
| 3 | OpenClaw 从 GitHub 拉取代码 |
| 4 | OpenClaw 加载 Agent，投入运行 |

### 从 OpenClaw 同步到 CC

| 步骤 | 内容 |
|------|------|
| 1 | OpenClaw 记录新的知识/需求 |
| 2 | 自动备份到 GitHub |
| 3 | CC 获取最新需求文档 |
| 4 | CC 开始开发/优化 |

## 六、技术栈

### Claude Code (CC)

- **语言**: Python
- **运行环境**: 本地电脑 / 安全服务器
- **版本控制**: Git + GitHub
- **擅长**: 复杂工程、安全敏感操作

### OpenClaw

- **语言**: Python (Agent)、Markdown (知识)
- **运行环境**: 云服务器
- **渠道**: 飞书、Telegram、手机端
- **擅长**: 随时响应、多 Agent 协同
