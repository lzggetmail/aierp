## 什么是绑定规则？

**绑定规则 = 路由规则**

告诉 OpenClaw：什么样的消息，应该给哪只龙虾处理。

---

## 匹配维度

| 维度 | 说明 |
|------|------|
| channel | 渠道（飞书、WhatsApp、Telegram） |
| accountId | 账号（personal、work） |
| peer.kind | 聊天类型（direct、group） |
| peer.id | 具体的人/群 |

---

## 匹配优先级

```
1. peer（具体群/人）  ← 最精确
2. accountId（账号）
3. channel（渠道）    ← 最宽泛
4. 默认龙虾           ← 兜底
```

---

## 配置示例

### 多渠道示例（需要多个通道）
```json
{
  "bindings": [
    { "agentId": "chat", "match": { "channel": "feishu" } },
    { "agentId": "deep", "match": { "channel": "telegram" } }
  ]
}
```

### 单渠道多群/人示例（志刚的实际情况）
```json
{
  "bindings": [
    {
      "agentId": "work",
      "match": {
        "channel": "feishu",
        "peer": { "kind": "group", "id": "工作群ID" }
      }
    },
    {
      "agentId": "main",
      "match": { "channel": "feishu" }
    }
  ]
}
```

**注意**：一个飞书应用（一个 App ID）可以服务多个 Agent，不需要多个机器人！

---

## 命令

```bash
# 查看绑定规则
openclaw agents list --bindings
```

---

## 注意事项

1. 规则顺序很重要（精确的放前面）
2. 没有匹配的规则用默认龙虾
