# 03-提示词工程技巧

> 🎯 **学习目标**：掌握设计高质量提示词的方法，精准控制 NotebookLM 输出

> ⏱️ **预计时间**：2 小时

> 📚 **前置要求**：完成 [[01-快速开始]] 和 [[02-资料准备与来源管理]]

---

## 💡 为什么提示词如此重要？

### 提示词质量 = 输出质量

```
模糊的提示词 → 泛泛的回答 → 难以使用

精准的提示词 → 深度的分析 → 直接可用
```

### NotebookLM 提示词的特点

与传统 AI 不同，NotebookLM 提示词需要：

```
✅ 明确指定来源（基于哪些文档）
✅ 说明分析框架（从哪些角度）
✅ 定义输出格式（如何呈现）
✅ 设定深度要求（多详细）
```

## 🎯 提示词核心框架

### 万能公式

```
[角色定位] + [任务目标] + [分析框架] + [输出要求] + [限定条件]

示例：
作为一位[资深管理咨询顾问]，
请[分析客户面临的数字化转型挑战]，
从[组织、技术、流程、人才]四个维度，
[以表格形式呈现每个问题的严重程度和影响]，
[仅基于上传的资料，不添加外部信息]。
```

### 五大要素

#### 1. 角色定位（Role）

```
明确：希望 AI 以什么角色进行分析

示例：
✅ "作为一位资深管理咨询顾问"
✅ "作为一位技术架构专家"
✅ "作为一位行业分析师"
✅ "作为一位财务专家"

❌ "帮我分析"（缺少角色定位）
```

#### 2. 任务目标（Task）

```
明确：要完成什么具体任务

示例：
✅ "请分析客户面临的主要挑战"
✅ "请对比三种解决方案的优劣势"
✅ "请提取文档中的所有关键数据"
✅ "请总结文档的核心观点"

❌ "分析一下文档"（不够具体）
```

#### 3. 分析框架（Framework）

```
明确：从哪些角度/维度进行分析

示例：
✅ "从以下维度分析：
   1. 市场环境
   2. 竞争格局
   3. 技术趋势
   4. 客户需求"

✅ "使用 SWOT 框架分析"

✅ "从成本、收益、风险三个角度评估"
```

#### 4. 输出要求（Output）

```
明确：希望以什么形式呈现

示例：
✅ "请以表格形式呈现"
✅ "请用 markdown 格式输出"
✅ "请按照以下结构：
   一、背景
   二、问题
   三、方案
   四、结论"

✅ "每点不超过 100 字"
```

#### 5. 限定条件（Constraint）

```
明确：有什么限制或特殊要求

示例：
✅ "仅基于上传的资料，不添加外部信息"
✅ "引用关键数据时要标注来源"
✅ "避免使用技术术语，用通俗语言"
✅ "每类问题不超过 5 个"
```

## 📋 基础提示词模板

### 模板 1：全局理解

```
请全面分析[文档主题/内容]，提供：

1. **核心议题**
   - 主要讨论的问题
   - 涉及的关键概念

2. **主要观点**
   - 列出 5-7 个核心观点
   - 每个观点用一句话概括

3. **关键信息**
   - 重要的数据、事实、案例
   - 按重要性排序

4. **结论建议**
   - 文档的主要结论
   - 提出的建议或行动项

请用结构化的方式呈现，方便后续制作 PPT。
```

### 模板 2：结构化提取

```
请从文档中提取[主题]相关信息，并按以下结构整理：

## 一、[类别 1]
1. 要点 1
   - 详细说明
   - 支撑数据/案例

2. 要点 2
   - 详细说明
   - 支撑数据/案例

## 二、[类别 2]
[同上结构]

## 三、[类别 3]
[同上结构]

要求：
- 每个类别提取 3-5 个要点
- 包含具体的细节和数据
- 标注信息来源
```

### 模板 3：对比分析

```
请对比分析文档中的[A]和[B]：

| 维度 | A | B | 优劣对比 |
|------|---|---|----------|
| 特点  |   |   |          |
| 优势  |   |   |          |
| 劣势  |   |   |          |
| 适用场景 |   |   |          |
| 实施难度 |   |   |          |
| 预期效果 |   |   |          |

## 综合评估
请说明：
1. 在什么情况下选择 A 更合适？
2. 在什么情况下选择 B 更合适？
3. 有没有可以结合的方式？
```

## 🎓 进阶提示词技巧

### 技巧 1：多轮对话设计

#### 第一轮：建立框架

```
请建立[主题]的分析框架，包括：
1. 需要分析的核心维度
2. 每个维度的关键要素
3. 各要素之间的关联

以结构化的思维导图形式呈现。
```

#### 第二轮：填充细节

```
基于刚才建立的分析框架，
请详细展开[维度 1]的内容：
1. 具体包含哪些要素
2. 每个要素的现状如何
3. 存在哪些问题
4. 有哪些改进空间
```

#### 第三轮：深度分析

```
针对[具体问题]，请进行深入分析：
1. 问题的根本原因是什么
2. 有哪些可能的解决方案
3. 每种方案的优劣势
4. 推荐方案及理由
```

#### 第四轮：总结提炼

```
基于以上分析，请总结：
1. 最核心的 3 个洞察
2. 最关键的 2 个建议
3. 最需要关注的 1 个风险
```

### 技巧 2：指定来源分析

```
请基于文档[来源名称]分析[主题]：
- 仅使用该文档中的信息
- 不参考其他来源
- 明确标注信息来源

示例：
"请基于《2025制造业数字化转型报告》分析行业趋势"
```

### 技巧 3：对比多来源

```
请对比分析以下来源中关于[主题]的论述：

**来源 A：[文档1]**
- 主要观点：
- 关键数据：

**来源 B：[文档2]**
- 主要观点：
- 关键数据：

**对比分析**
- 共识：哪些观点一致？
- 差异：哪些观点不同？
- 可能原因：
```

### 技巧 4：引导式发现

```
我正在研究[主题]，请帮我：

1. **发现盲点**
   - 文档中可能遗漏的重要维度
   - 需要进一步探索的问题

2. **连接关联**
   - 表面不相关但实际有关联的概念
   - 可以整合的信息点

3. **提炼洞察**
   - 跨文档的深层洞察
   - 非显而易见的模式
```

### 技巧 5：验证和质疑

```
请对文档中的[观点/数据]进行验证：

1. **数据支撑**
   - 有哪些具体数据支撑？
   - 数据是否足够充分？

2. **逻辑检查**
   - 论证是否合理？
   - 是否存在逻辑漏洞？

3. **潜在假设**
   - 隐含了哪些假设？
   - 这些假设是否成立？

4. **反向思考**
   - 有没有相反的证据？
   - 观点是否过于绝对？
```

## 🎯 场景化提示词

### 场景 1：企业解决方案

#### 全局分析

```
作为一位资深管理咨询顾问，
请全面分析客户的企业数字化转型需求：

## 分析框架
从以下 7 个维度进行分析：
1. 战略一致性
2. 组织准备度
3. 技术可行性
4. 流程优化空间
5. 数据基础
6. 人才能力
7. 投资回报

## 输出要求
对每个维度，请说明：
- 现状评估（1-5 分）
- 主要问题
- 改进方向
- 优先级（高/中/低）

## 格式要求
使用表格形式呈现，便于制作 PPT。
```

#### 解决方案设计

```
基于文档内容，请设计企业数字化转型解决方案：

## 方案架构
1. **总体框架**
   - 核心理念
   - 主要模块
   - 模块间关系

2. **详细设计**
   对每个模块说明：
   - 功能定位
   - 核心能力
   - 技术实现
   - 实施难度
   - 预期收益

3. **实施规划**
   - 分阶段实施路径
   - 每阶段里程碑
   - 时间安排
   - 资源需求

4. **风险控制**
   - 主要风险
   - 应对措施
   - 保障机制

请以专业方案文档格式输出。
```

## 🔧 提示词优化技巧

### 优化 1：明确化

#### ❌ 模糊的提示词
```
"分析一下这个方案"
"总结文档内容"
"找出关键问题"
```

#### ✅ 明确的提示词
```
"从成本、收益、风险三个维度分析该方案的可行性"
"总结文档中关于数字化转型趋势的核心观点（5-7点）"
"找出客户面临的三大关键问题，并分析严重程度"
```

### 优化 2：结构化

#### ❌ 非结构化
```
"告诉我关于这个项目的所有信息"
```

#### ✅ 结构化
```
请按以下结构分析项目：

## 项目背景
- ...

## 项目目标
- ...

## 实施方案
- ...

## 预期成果
- ...
```

### 优化 3：量化

#### ❌ 非量化
```
"列出一些问题"
"总结几个要点"
```

#### ✅ 量化
```
"列出 5-7 个主要问题，按严重程度排序"
"总结 3 个核心观点和 5 个支撑论据"
"每个类别不超过 3 项，每项不超过 50 字"
```

### 优化 4：示例化

#### ❌ 无示例
```
"请以表格形式呈现"
```

#### ✅ 有示例
```
请以如下表格形式呈现：

| 问题 | 现状 | 目标 | 差距 | 优先级 |
|------|------|------|------|--------|
| ...  | ...  | ...  | ...  | ...    |
```

## 🎓 提示词设计流程

### STEP 1: 明确目标

```
问自己：
1. 我要完成什么任务？
2. 期望得到什么输出？
3. 输出用于什么场景？

示例：
- 任务：分析客户需求
- 输出：结构化的需求清单
- 场景：方案撰写
```

### STEP 2: 选择框架

```
选择合适的分析框架：
- SWOT（优劣势分析）
- 5Why（根本原因分析）
- PESTLE（环境分析）
- 波特五力（竞争分析）
- 或自定义框架
```

### STEP 3: 设计输出

```
指定输出格式：
- 表格（便于对比）
- 列表（清晰明了）
- 大纲（结构化）
- 报告（完整详细）
```

### STEP 4: 设定限制

```
明确限制条件：
- 字数限制
- 数量限制
- 来源限制
- 时间限制
```

### STEP 5: 测试优化

```
测试提示词效果：
- 输出是否符合预期？
- 是否需要调整框架？
- 是否需要增加细节？

根据反馈迭代优化
```

## ⚠️ 常见错误

### 错误 1：过于宽泛

```
❌ "分析一下文档"

✅ "从市场、技术、财务三个维度分析该项目的可行性"
```

### 错误 2：缺少结构

```
❌ "告诉我关于这个项目的所有信息"

✅ "请按以下结构分析：背景、目标、方案、风险、收益"
```

### 错误 3：一次性要求太多

```
❌ "请全面分析项目的所有方面，包括市场、技术、财务、
组织、运营、风险等，并给出详细建议"

✅ 拆分成多轮对话：
第1轮：市场分析
第2轮：技术分析
第3轮：财务分析
...
```

### 错误 4：不指定格式

```
❌ "整理这些问题"

✅ "请用表格形式整理，包括：
问题描述、严重程度、影响范围、应对措施"
```

### 错误 5：直接要求生成，导致通用内容

```
❌ "请生成企业 ERP 升级方案"
   → 会生成通用的、套话式的方案

✅ 分三步走：

第 1 步：先提取独特内容
"请从会议记录中提取：
1. 客户的具体情况
2. 我们讨论的具体方案
3. 会议中的关键数据
4. 讨论中的独特观点"

第 2 步：确认提取内容
"请确认我们讨论的要点是：[列出要点]"

第 3 步：基于提取内容生成
"基于以上提取的会议内容，
生成客户专属的解决方案报告。
要求：
- 使用会议中的原话
- 保持会议的独特性
- 不要使用通用模板
- 会议没提到的不要编造"
```

#### 为什么会生成通用内容？

NotebookLM 倾向于使用通用框架，除非：
1. ✅ 明确要求提取文档的独特内容
2. ✅ 反复强调"基于文档"、"不要通用"
3. ✅ 要求使用原话和具体表述
4. ✅ 先提取，再生成（不要一步到位）

#### 避免通用内容的关键词

```
使用这些表述：
- "从文档中提取具体内容"
- "基于会议讨论的..."
- "使用会议中的原话"
- "保持讨论的独特性"
- "不要使用行业套话"
- "如果文档没提到，说明'未讨论'"
```

#### 实战示例

❌ **错误的提示词**：
```
"生成客户数字化转型方案"
→ 生成的是通用的、套话式的方案
```

✅ **正确的提示词**：
```
"首先，请从会议记录中提取：
1. 客户的具体情况（行业、规模、问题）
2. 我们讨论的具体方案（模块、功能、思路）
3. 会议中的数据（效率、成本、时间）
4. 独特观点（不同于通用方案之处）

然后，基于提取的内容生成报告：
- 使用会议中的原话
- 保持我们讨论的独特性
- 不要用行业套话
- 每部分都要引用会议内容"
→ 生成的是客户专属的、具体的方案
```
