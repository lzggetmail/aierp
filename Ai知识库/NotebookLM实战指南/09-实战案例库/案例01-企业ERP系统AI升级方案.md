# 实战案例 01：企业 ERP 系统 AI 升级解决方案

> 📅 **项目日期**：2026-03-26

> ⏱️ **项目用时**：约 4 小时

> 🎯 **项目目标**：基于会议讨论记录，生成客户汇报 PPT 和完整方案

---

## 📋 项目背景

### 项目来源
客户原本使用一套 ERP 系统，但出现了很多管理难题，希望通过 AI 升级方案解决这些问题。团队进行了深入讨论，分析了客户痛点、行业问题，并提出了初步解决方案。

### 项目需求
1. **整理会议内容**：将 1 小时的讨论录音转录成结构化的方案
2. **生成解决方案**：基于讨论内容，形成完整的企业解决方案
3. **制作汇报 PPT**：生成面向客户高管的演示文稿（30 分钟版本）

### 项目特点
- ✅ 有完整的会议转录文档（约 1.5 万字）
- ✅ 团队已进行深入讨论，有明确思路
- ✅ 需要高质量输出，用于客户汇报
- ❌ 暂时没有添加额外的参考资料（时间紧迫）

## ⚠️ 重要修正：避免生成通用内容

### 遇到的问题

在使用初始提示词生成报告时，NotebookLM 输出的是**通用性的研究报告**，而不是基于会议讨论的**客户专属方案**。

### 问题原因

1. **提示词过于宽泛**
   - 使用了"生成企业 ERP 升级方案"这类通用表述
   - NotebookLM 会自动套用行业通用框架

2. **缺少具体引导**
   - 没有强调要提取会议中的**独特内容**
   - 没有要求基于团队讨论的**具体方案**

3. **上下文不够**
   - 直接要求生成，没有先提取会议的独特观点
   - 缺少"基于会议记录"的反复强调

### 修正方法

#### ✅ 正确的三步流程

```
第 1 步：提取会议独特内容
第 2 步：组织和确认
第 3 步：基于提取内容生成报告
```

#### Step 1：先提取会议核心内容

```markdown
请仔细分析会议记录，提取以下具体内容：

## 1. 客户具体情况
- 客户是什么行业的？
- 客户当前使用什么系统？
- 客户具体面临哪些困难？（请逐条列出会议中提到的）

## 2. 团队提出的具体方案
会议中我们团队具体提出了哪些方案要素？
- 有哪些具体的模块或功能？（原话）
- 实施思路是什么？（原话）
- 有哪些具体的创新点？（原话）
- 有哪些具体的实施建议？（原话）

## 3. 讨论中的关键数据
会议中提到了哪些具体数字？
- 效率提升的数据
- 成本相关的数据
- 时间相关的数据

## 4. 讨论中的独特观点
这次讨论中有哪些独特的、不同于通用方案的观点？
```

**关键**：这一步的目的是让 NotebookLM 先理解会议的**独特内容**，而不是套用通用框架。

#### Step 2：生成报告时反复强调来源

```markdown
基于刚才提取的会议内容，生成客户专属的解决方案报告：

## ⚠️ 核心要求
- 必须使用会议中讨论的具体内容
- 不要使用通用模板或套话
- 每个部分都要基于会议中的具体讨论
- 如果会议中没提到的内容，不要编造
- 使用"会议中提到"、"我们讨论了"等表述

## 报告结构
```

### 关键技巧总结

#### 技巧 1：分三步走
```
第 1 步：提取 - "请从会议中提取具体内容..."
第 2 步：确认 - "请确认我们讨论的要点是..."
第 3 步：生成 - "基于以上提取的内容，生成..."
```

#### 技巧 2：强调来源
```
在提示词中反复强调：
- "基于会议记录"
- "从会议中提取"
- "会议中提到的"
- "不要使用通用内容"
```

#### 技巧 3：要求原话
```
- "请使用会议中的原话"
- "用我们讨论时的表述"
- "保持会议的独特性"
```

#### 技巧 4：明确边界
```
"如果会议中没有提到，请说明'未讨论'或'待补充'，
不要编造或套用通用内容"
```

### PPT 提示词也要同样修正

```markdown
请为这个客户生成汇报 PPT，严格要求：

## ⚠️ 核心原则
- 必须基于会议中讨论的具体内容
- 不使用通用模板
- 每页内容都要来自会议记录
- 如果会议没提到的内容，用"待讨论"或跳过

## PPT 结构（20 页）

### 第 1 页：封面
- 标题：[会议中确定的项目名称]
- 副标题：[会议中的价值主张]

### 第 2 页：客户背景（从会议中提取）
- 客户行业：[会议中提到的]
- 当前状况：[会议中描述的]
- 核心挑战：[会议中列出的 3-5 个]

### 第 3 页：我们诊断的问题（会议原话）
会议中我们具体诊断出哪些问题？
- 问题 1：[会议中的原话]
- 问题 2：[会议中的原话]
- 问题 3：[会议中的原话]

[继续...]

## 关键要求
1. 每页都要写明"基于会议讨论"
2. 使用会议中的原话
3. 保持会议讨论的独特性
4. 不要用行业套话
5. 会议没提到的内容不要编造
```

### 修正效果

使用修正后的提示词：
- ✅ 生成的是客户专属方案
- ✅ 内容基于会议讨论
- ✅ 保留了独特的观点和表述
- ✅ 避免了行业套话和通用模板

### ⚠️ 遇到的问题

1. **资料不够丰富**
   - 问题：只有会议记录，缺少行业数据支撑
   - 影响：部分数据不够具体（如成本节约比例）
   - 解决：可以在后续补充行业报告

2. **有些内容不够详细**
   - 问题：实施细节不够具体
   - 影响：方案的可操作性需要加强
   - 解决：通过追问补充细节

3. **时间分配**
   - 问题：生成 PPT 用时较长
   - 影响：需要耐心等待
   - 解决：合理安排时间，可以先做其他事

### 📝 改进建议

1. **如果时间充裕**
   ```
   □ 添加 3-5 份行业报告
   □ 补充成功案例
   □ 增加 ROI 详细分析
   ```

2. **如果追求更高品质**
   ```
   □ 多轮对话深化内容
   □ 逐页精细优化
   □ 添加更多数据图表
   ```

3. **如果时间紧张**
   ```
   □ 使用模板直接生成
   □ 聚焦核心页面
   □ 简化次要内容
   ```
