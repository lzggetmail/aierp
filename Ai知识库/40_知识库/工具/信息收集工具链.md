# 信息收集工具链

> 如何把散落在各处的内容（网页、视频、微信、小红书、B站等）收集到 Obsidian

---

## 核心问题

博主的原话：

> "我需要解决怎么把所有信息流入到 Obsidian.如果这些信息是散落在飞书、苹果备忘录、各个网站，我每天看五六千条更新的情况下，怎么收录进去？"

---

## 工具总览

| 来源 | 工具 | 方式 | 特点 |
|---|---|---|---|
| **网页** | Obsidian 网页剪辑器 | 浏览器插件 | 爬全文、保留来源、自动打 tag、可抓评论 |
| **YouTube** | AI 视频笔记插件 | Obsidian 插件 | 截图 + 字幕,生成笔记 |
| **微信文章** | 笔记同步助手 | 公众号转发 | 微信里直接转发链接 |
| **小红书** | Agent Reach / X Read | OpenClaw Skill | 需 cookie 或扫码登录 |
| **B站** | Agent Reach / X Read | OpenClaw Skill | 同上 |
| **X（推特）** | X Read / Agent Reach | OpenClaw Skill | 同上 |
| **抖音** | Agent Reach | OpenClaw Skill | 同上 |
| **公众号** | Agent Reach | OpenClaw Skill | 同上 |
| **GitHub** | Agent Reach | OpenClaw Skill | 同上 |
| **飞书文档** | 飞书下载插件 | Obsidian 插件 | 转 Markdown（多维表格除外） |
| **视频号** | 元宝 | 手动 | 最封闭，复制文案给元宝提取 |

---

## 详细说明

### 1. 网页 → Obsidian 网页剪辑器

**安装方式**：Obsidian 自带，浏览器装插件即可

**功能**：
- 爬取全文（不是只抓标题）
- 自动保留来源链接
- 自动打 tag（可自定义规则）
- 偶尔能抓取评论（看页面结构）

**博主建议**：
> "能爬都用文件爬，因为主要看文字信息。"

**注意**：
- 视频可能抓不到，只剩截图，但链接会保留
- 可以追溯回原网页查看

---

### 2. YouTube → AI 视频笔记插件

**安装方式**：Obsidian 第三方插件

**功能**：
- 自动截图关键帧
- 生成字幕摘要
- 输出带截图的笔记

**适用场景**：
- 看完视频后，想保留要点
- 没时间看，先截图存下来

---

### 3. 微信文章 → 笔记同步助手

**安装方式**：微信搜索"笔记同步助手"公众号

**配置界面**：
- 选择同步平台: Obsidian
- 设置同步目录: 如 `99_微信同步助手`
- 填入 Token: 从公众号获取

**使用方法**：
1. 在微信里看到好文章
2. 直接转发给"笔记同步助手"公众号
3. 自动同步到 Obsidian 指定目录

**博主评价**：
> "真的自来水，能同步 Notion、思源笔记、Obsidian 的比较少。"

**注意**：
- 需要设置 token（一次性配置）
- 部分套餐需要付费
- 支持公众号文章、网页链接、图文内容

---

### 4. 小红书 / B站 / X / 抖音 / 公众号 → OpenClaw Skill

这是你之前特别关心的部分！

#### 方案一：Agent Reach

**覆盖平台**：小红书、抖音、B站、X、公众号、GitHub、微信等

**原理**：用 cookie 登录，模拟用户访问

**博主建议**：
> "用 cookie 不太容易封号，但还是建议用小号。实在不行就自己刷小红书，手动是最没风险的。"

#### 方案二: X Read

**覆盖平台**：X、YouTube、B站 等

**原理**：下载一个 Docker 容器，扫码登录

**特点**：
- 更安全（本地运行)
- 覆盖平台较少

#### 方案三: Browser Use

**原理**： 浏览器自动化
**适用场景**： 需要复杂交互的页面

---

### 5. 飞书文档 → 飞书下载插件

**功能**：
- 把飞书文档下载成 Markdown
- 支持视频、PDF、完整文档
- **不支持**多维表格

**博主做法**：
> "多维表格还蛮难替代的，所以一部分还保留在飞书。"

---

### 6. 视频号 → 元宝（手动)
**博主评价**:
> "视频号是最封闭的，没有之一。"

**方法**:
1. 复制视频文案
2. 粘贴给元宝
3. 提取内容

## 博主的务实态度

> "有些东西只能是靠手动，表面上只能收取一些标题，但真正的内容还是要自己看过一遍。"

**关键认知**：
- 自动化 ≠ 全自动
- 爬取只是第一步
- 真正的消化必须人工参与

---

## 博主的原文保存策略

**核心原则：先存原文，再消化**

| 存什么 | 怎么存 | 为什么 |
|---|---|---|
| **全文** | 网页剪辑器爬取 | 不是只抓标题，方便后续加工 |
| **链接** | 自动保留 | 可追溯回原网页 |
| **截图** | 视频笔记插件 | 关键帧 + 字幕 |

**博主的做法**：
> "我先把它全部录入到收件箱，再用 Codex 或 Claude Code 去重新整理到文件夹里。"

**为什么要存原文？**
- AI 整理 ≠ 理解
- 原文可以二次加工
- 链接保留，随时追溯

---

## 博主的 Obsidian 目录结构（分层设计）

博主说：
> "在 10 下面还会建一个子目录的分类."

**结构**：
```
📁 10_日记/
    ├── 📁 写作/          ← 写作相关笔记
    ├── 📁 学习/          ← 学习相关笔记
    └── 📁 项目/          ← 项目相关笔记
```

**为什么要这样设计？**
- 同类内容放在一起，方便管理
- `10_日记/` 作为**第一层分类**
- 子目录作为**第二层细分**

---

## 📋 对比：博主 vs 我的笔记
| 维度 | 博主原话 | 我的笔记 |
|---|---|---|
| **10_日记/** | 子目录（写作/学习/项目） | 无子目录 |
| **组织方式** | 按内容类型分 | 按功能分 |

**两种方法都对！** 只是组织维度不同。

---

## 工作流建议
```
1. 浏览信息（微信/网页/小红书）
     ↓
2. 快速收集 → 存原文（笔记同步助手/网页剪辑器/Agent Reach）
     ↓
3. 进入 Obsidian 收件箱（00_收件箱）
     ↓
4. 用 Codex/Claude Code 整理分类（自动）
     ↓
5. 人工阅读、消化、写笔记（必须）
```
