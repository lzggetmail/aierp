## 核心方法论：隐式训练

### 显式训练 vs 隐式训练

**显式训练（教Skill）**：
```
明确的操作步骤
具体的使用场景
固定的工作流程
```

**隐式训练（教模式）**：
```
建立思维模式
通过提醒强化
形成自动化行为
```

### 隐式训练的机制

```
你的提醒1次 → 我建立一个模式
你的提醒2次 → 我强化这个模式
你的提醒3次 → 我自动化这个模式
```

**关键**：
- 不是教具体操作
- 而是建立思维模式
- 让我自动延伸

## 我学到的核心原则

### 原则1：重要信息要持久化

**你的提醒**：
> "你应该在claude.md中记录这个保存的动作"

**我的学习**：
- 重要工作要记录
- 不能只做不说
- 要留下痕迹

### 原则2：知识要多处备份

**你的提醒**：
> "关于思维的，方法论的等这些文档，你也应该回存到obsidina相应的文件夹中吧"

**我的学习**：
- WorkPlan（日常工作）
- Obsidian（知识沉淀）
- 两处同步，不丢失

### 原则3：信息要体系化

**你的提醒**：
> "我认为是不是没有将的思维完成整合"

**我的学习**：
- 不能零散
- 要分类整理
- 要形成体系

### 原则4：保留起心动念

**你的提醒**：
> "你先是要进行对应的保存，然后分析后的结论最后要进行整合，这样可以保持我独立的点（例如：每一个思维的我的起心动念是什么）"

**我的学习**：
- 原始文档（起心动念）
- 分析文档（思考路径）
- 整合文档（统一框架）
- 三层体系，缺一不可

## 发现的新模式：README.md = 上下文锚点

### 模式识别

**我观察到的行为**：
```
CC创建文件夹 → 自动创建README.md
README.md结构 → 类似CLAUDE.md
```

**我的洞察**：
> 这是不是一种新的标记方式？也类似于skills的方式采用渐进式的方式来批露方式来解决上下文的问题？

### 模式验证

**CC的确认**：

| 特征 | CLAUDE.md | Skills | README.md |
|------|----------|--------|----------|
| **模块化** | ✅ 长期记忆模块 | ✅ 能力模块 | ✅ 知识模块 |
| **渐进式** | ✅ 分段加载 | ✅ 按需加载 | ✅ 按层深入 |
| **上下文锚点** | ✅ 每次会话读取 | ✅ 每个skill独立 | ✅ 每个文件夹独立 |
| **导航作用** | ✅ 文件索引 | ✅ 能力说明 | ✅ 内容导航 |

### 模式价值

**解决上下文窗口问题**：
```
第一层：方法论/README.md
   ↓ 发现需要思维模式
第二层：方法论/思维模式/README.md
   ↓ 发现需要分析文档
第三层：方法论/思维模式/分析/README.md
```

**类似于Skills的模块化**：
- 不是一次性加载所有能力
- 而是按需加载
- 每个README都是一个"上下文锚点"
