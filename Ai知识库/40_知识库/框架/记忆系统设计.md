# 记忆系统设计

> 博主的双层记忆 + OpenClaw 的 MEMORY.md

---

## 🧠 博主的双层记忆

### 第一层：原始记忆（MEMORY.md)

**格式**：
```markdown
# [日期] 记忆内容

## 内容
[具体的事实/信息]

## 生效规则
[这个记忆如何影响未来的对话]

## 影响力
[高/中/低]
```

**作用**： 记录原始信息,防止遗忘

---

### 第二层: QMD 本地向量库

**功能**：
- 本地运行的小型 embedding 模型
- 减少 token 消耗
- 快速检索相关记忆

**工作原理**：
```
原始记忆 → QMD 夣理 → 向量嵌入 → 快速检索
```

**博主建议**：
> "QMD 就是本身有 markdown 的记忆的情况下，做了一个很小的 embedding 的模型，相当于下载一个你本地电脑能够随便跑的大模型,然后让那个模型去获得支持之后,再发给你的更高一级的。像 Claude 这些费钱一点的模型。这样会省钱。"

---

## 📊 两种记忆对比

 | 维度 | MEMORY.md | QMD 向量库 |
|---|---|---|---|
| **存储方式** | Markdown 文件 | 向量数据库 |
| **检索方式** | AI 直接读取 | 相似度搜索 |
| **适用场景** | 精确记录 | 快速召回 |
| **成本** | Token 多 | 知省 token |

---

## 🔄 博主的工作流

```
对话产生信息 → 写入 MEMORY.md（原始记忆）
                ↓
        QMD 定期处理 → 生成向量索引
                ↓
        新对话时 → QMD 快速检索相关记忆
                ↓
        AI 结合上下文回答
```

---

## 💡 博主建议

> "用 QMD 做 embedding,相当于下载一个本地模型，然后在本地跑。这样既省钱,又能保持记忆检索能力。"

---

## 🛡️ 齿轮检查

博主提到一个技巧：**定期测试 AI 是否遗忘**

**方法**：设定一个"密码"，比如 "卡真棒"

```
你: 说 "卡真棒"
AI: 回复 "卡真棒" → 还记得
AI: 回复错误 → 开新对话
```

**作用**： 避免在长对话中重复解释

检测 AI 是否真的"记住"了。

## 📝 讯息遗忘应对

### 博主做法
> "六了之后我们会有一个新的任务,让他自己去判断。然后他会学习我的习惯。用第一个 skill，就是让他先写下来,让他开口读一下也行。这样才会知道你的偏好。新发一个问题的话,他 大概率就需要做一个记忆备份,然后再开新的。"

**本质**： 让 AI 自己写日记,记录你的偏好
