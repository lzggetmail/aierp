# 风险与注意事项

> 使用 AI 的过程中的风险和应对策略

---

## 🛡️ 主要风险

### 1. AI 误删文件

**风险**： AI 可能误操作，删除你的文件

**博主做法**：
> "我做了个很狠的处理： 我把本地除了 download 以外的所有文件夹传给了 iCloud。这样 AI 就算删也删不掉我"

**应对策略**：

| 方案 | 操作 | 特点 |
|---|---|---|
| **Git 备份** | 私有仓库 | ⭐⭐⭐ 最推荐 |
| **iCloud 同步** | 实时同步 | ⭐⭐⭐ 推荐 |
| **虚拟机隔离** | 独立环境 | ⭐⭐⭐ 最安全 |

---

### 2. 中转 API 不稳定

**风险**： 中转 API 可能掉线、影响使用

**博主建议**：
> "最靠谱的是 Open Router，永远不会掉线。"

**应对**：
- 备选方案： 多个中转
- 降级处理： 先用免费模型

---

### 3. 免费额度用完

**风险** : 免费额度用完，突然收费

**应对**：
- 监控用量
- 及时刷新额度
- 切换到免费模型

---

### 4. 小红书爬取封号

**风险** : 频繁爬取可能封号

**博主建议**：
> "用小号，或者手动刷。手动是最没风险的。"

**应对**：
- 用小号
- 降低频率
- 重要内容手动

---

### 5. 网页剪辑器掉视频

**风险** : 网页剪辑器可能抓不到视频，只剩截图

**应对**：
- 保留原链接
- 手动补充视频信息

---

## 🛡️ 博主的极端方案

### 虚拟机 + iCloud
**博主做法**：
```
本地电脑
    ├── 虚拟机（跑 OpenClaw）
    └── iCloud（备份所有文件）
```

**效果**：
- AI 只能访问虚拟机
- 虚拟机删了 → iCloud 还有备份
- 本地文件不受影响

**博主警告**：
> "大家千万不要学我，真的不建议大家这样玩。iCloud 要扩展到 2TB 版本。"

---

### Git + 私有仓库
**操作**：
```bash
git init
git remote add origin https://github.com/用户名/私有仓库.git
git push -u origin main
```

**效果**：
- 每次修改都有版本记录
- 可以回退到任意版本
- AI 删了也能恢复

---

## 📊 风险等级

| 风险 | 等级 | 应对 |
|---|---|---|
| **AI 删文件** | 🔴 高 | Git + iCloud |
| **中转掉线** | 🟡 中 | 备选方案 |
| **额度用完** | 🟡 中 | 监控用量 |
| **封号** | 🟡 中 | 用小号 |
| **掉视频** | 🟢 低 | 保留链接 |

---

## 💡 博主建议
> "做好备份隔离， 用 iCloud 或 git。但是不建议大家像我这样极端。"

**安全原则**：
1. **永远有备份**
2. **隔离运行环境**
3. **监控用量和额度**
4. **重要内容手动确认**
