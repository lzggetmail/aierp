## 一、问题背景

### 1.1 客户的典型反应

**客户原话**：
- "我没数据，怎么做AI？"
- "等我数据完善了再说"
- "你们能不能等我把系统上了再来？"
- "我们数据太乱了，没法用"

### 1.2 传统做法的困境

```
传统流程:
客户说要上AI → 要求完善数据 → 客户觉得麻烦 → 项目停滞

问题:
- 数据完善是长期过程（需要3-6个月）
- 客户看不到眼前价值
- 容易被竞品趁虚而入
- 客户对"数据治理"有抵触情绪
```

### 1.3 市场信号（来自晟起项目）

| 信号 | 说明 |
|------|------|
| 小王总："你们有跑通的东西吗？" | 客户不会为概念买单，只要看到效果 |
| 胡总："感冒了先吃药" | 客户想要短平快的工具，不是大体系 |
| 杨总用"一毛钱一张图纸" | 客户对价格的敏感度极高 |

### 1.4 问题的本质

**不是"数据不齐全"，而是"不知道哪些数据重要"**

客户每天都在开会讨论问题，但这些讨论：
- 没有被记录
- 没有被分析
- 没有被提炼成数据维度
- **这就是我们切入的机会**

## 二、核心思想

### 2.1 创新方法

**核心思想**：
> **"用对话式追问来补全数据，而不是等待数据完善"**

**对比**：
```
传统方式: 数据完善 → 上系统 → AI分析
创新方式: AI参与 → 对话补全 → 形成数据 → 持续优化
```

### 2.2 为什么这样做能行？

1. **客户每天都在讨论问题**
   - "今天产量怎么下降了？"
   - "为什么质量投诉多了？"
   - "这个订单为什么延期了？"

2. **这些讨论就是数据**
   - 下降50个 → 需要记录每日产量
   - 材料问题 → 需要记录供应商到货时间
   - 人员请假 → 需要记录实际出勤

3. **我们的价值**
   - 参与会议，记录讨论
   - AI分析，提炼数据维度
   - 设计方案，补全数据
   - 建立监控，持续优化

### 2.3 核心优势

| 优势 | 说明 |
|------|------|
| ✅ 不要求客户先完善数据 | 降低门槛，快速启动 |
| ✅ 客户看不到额外工作量 | 无感采集，自然融入 |
| ✅ 每周都能看到价值 | 分析报告，立竿见影 |
| ✅ 成本低，易成交 | 5000-10000元试点 |

## 三、实施方法论（六步法）

### 第一步：参与客户会议

**目的**：理解客户真实的业务场景和问题

**具体做法**：
1. 提出参与每周例会
2. 使用录音/录像设备记录
3. 观察数据异常时的讨论过程
4. 记录老板追问的问题

**设备准备**：
- 录音笔（推荐）或手机录像
- 需提前征得客户同意
- 说明目的是"更好地理解业务"

**话术示例**：
> "胡总，为了更准确地理解您的业务，我能否参加您每周的管理例会？我会录音记录，方便后续分析。"

**注意事项**：
- 第一次参会要说明目的，消除顾虑
- 录音要承诺保密
- 尽量不干扰正常会议流程
- 重点记录"老板追问"的场景

---

### 第二步：识别数据异常

**目的**：找到值得追问的数据点

**示例场景**：
```
老板: "今天产量怎么只有50个？昨天不是100个吗？"
厂长: "今天材料没来，停电了2小时，小李请假..."
```

**关键点**：
- 记录具体的数值对比（100→50）
- 记录给出的原因（材料、停电、请假）
- 注意被忽略的因素（没人提到设备故障）

**识别技巧**：
- 关注老板的"为什么"
- 关注解释中的"因为"
- 关注数据的"突然变化"
- 关注多人讨论的"热点"

---

### 第三步：对话式追问

**目的**：通过追问获取隐性数据

**追问示例**：

| 场景 | 追问方式 |
|------|----------|
| 产量下降 | "今天比昨天少了50个，分别是什么原因？各影响多少？" |
| 质量问题 | "这批退货是因为材料问题还是工艺问题？比例如何？" |
| 人员缺勤 | "本周实际出勤人数是多少？请假/病假/事假各多少？" |
| 设备故障 | "这台机器本周故障几次？平均修复时间多久？" |
| 订单延期 | "这个订单延期是因为材料没到还是产能不足？" |

**技巧**：

1. **量化追问**：不接受"大概"、"差不多"，要具体数字
2. **拆解追问**：将问题拆解为多个维度
3. **持续追问**：追问"为什么"、"具体是多少"
4. **记录矛盾**：不同人说的不一样的地方

**追问时机**：
- 会议中适时插话（如果允许）
- 会后单独追问（更从容）
- 每周固定时间复盘

---

### 第四步：AI分析整理

**目的**：从对话中提炼数据维度

**操作流程**：

#### 4.1 录音转文字

**方法**：
- 使用录音转文字工具（如讯飞听见）
- 或直接发送录音给CC分析
- 手动整理重点片段

#### 4.2 CC分析提问

```
请分析以下会议记录:

**会议背景**：晟起周会，讨论本周产量异常
**参会人**：胡总、厂长、车间主任

**会议记录**：
[粘贴会议记录内容]

**任务**：
1. 识别提到的数据异常
2. 总结影响数据的关键因素
3. 提炼需要采集的数据维度
4. 给出数据采集建议
```

#### 4.3 CC输出示例

```markdown
## 会议分析报告

### 数据异常识别
- 产量：昨日100个 → 今日50个（下降50%）
- 质量投诉：本周3起（上周0起）
- 设备故障：3号机停机2次

### 影响因素（按频次）
1. 材料供应问题（5次提及）
   - 材料延迟到货（3次）
   - 材料质量问题（2次）
2. 设备故障（3次提及）
   - 3号机老化（2次）
   - 5号机故障（1次）
3. 人员缺勤（2次提及）
   - 小李请假（1次）
   - 小王病假（1次）

### 建议采集的数据维度

#### 优先级1（立即采集）
| 维度 | 采集频率 | 采集方式 | 责任人 |
|------|----------|----------|--------|
| 每日产量 | 每天 | 系统自动 | 车间主任 |
| 材料到货时间 | 每批次 | 仓库录入 | 仓库主管 |
| 设备运行时间 | 每天 | 设备联网 | 设备科 |

#### 优先级2（逐步建立）
| 维度 | 采集频率 | 采集方式 | 责任人 |
|------|----------|----------|--------|
| 实际出勤人数 | 每天 | 考勤系统 | 人事 |
| 质量投诉记录 | 每起 | 客服录入 | 质检部 |
| 设备故障记录 | 每次 | 维修录入 | 设备科 |

### 数据采集建议
1. 先采集每日产量（最简单，价值最大）
2. 逐步增加材料到货时间记录
3. 设备数据可以后期联网采集
```

### 第五步：形成数据字段

**目的**：将对话转化为可采集的数据结构

**示例**：

从"材料供应问题"提炼出：
```python
{
  "字段名称": "材料到货情况",
  "业务含义": "记录供应商材料到货的及时性",
  "采集频率": "每批次",
  "数据类型": {
    "计划到货时间": "datetime",
    "实际到货时间": "datetime",
    "延迟时长": "int(小时)",
    "影响产线": "text",
    "供应商名称": "text"
  },
  "责任人": "仓库主管",
  "采集方式": "仓库收货时录入",
  "校验规则": "实际到货时间不能晚于生产开始时间"
}
```

**设计原则**：

1. **数据字段要能回答对话中发现的问题**
   - ❌ "仓库温度" - 对话中没人提
   - ✅ "材料到货时间" - 对话中反复提

2. **采集方式要考虑客户实际能力**
   - ❌ "用IoT设备自动采集" - 客户没有
   - ✅ "仓库收货时录入" - 简单可行

3. **优先级：自动采集 > 简单录入 > 复杂计算**

### 第六步：持续跟踪优化

**目的**：建立正向循环

**循环机制**：

```
┌────────────────────────────────────────┐
│  日常工作: 数据录入                    │
├────────────────────────────────────────┤
│  AI监控: 识别异常                      │
│  - 产量突然下降                        │
│  - 质量投诉增加                        │
│  - 材料延迟增多                        │
├────────────────────────────────────────┤
│  自动追问: 发送通知给相关人员          │
│  "今日产量下降20%，请说明原因"         │
├────────────────────────────────────────┤
│  记录原因: 补充数据维度                │
│  - 材料、设备、人员？                  │
│  - 各影响多少？                        │
├────────────────────────────────────────┤
│  优化规则: 调整采集策略                │
│  - 增加新的数据维度                    │
│  - 调整采集频率                        │
└────────────────────────────────────────┘
```

**AI能力**：
- ✅ 自动识别异常数据
- ✅ 自动发送追问通知
- ✅ 自动生成分析报告
- ✅ 自动建议改进措施

**持续优化**：
- 每周回顾数据采集效果
- 识别重复出现的问题
- 调整数据采集策略
- 逐步完善数据模型

## 十、FAQ

### Q1：这个方法适合所有客户吗？

**A**：不是。最适合的客户特征：
- ✅ 中小企业（50-500人）
- ✅ 数据不齐全，但有管理会议
- ✅ 老板有改善意愿，但不知道怎么做
- ✅ 对AI有兴趣，但担心成本

不适合的客户：
- ❌ 大型企业（已有完善的数据体系）
- ❌ 没有管理会议的企业
- ❌ 对AI完全不感兴趣

### Q2：如果客户拒绝录音怎么办？

**A**：有几个替代方案
1. 只旁听，会后凭记忆整理
2. 降低试点价格（如3000元）
3. 说明我们可以签保密协议
4. 先做一次免费分析，展示价值

### Q3：试点后客户不转化怎么办？

**A**：
1. 控制预期：5000元就是买分析报告，不承诺转化
2. 展示价值：让客户看到持续的价值
3. 分阶段报价：降低长期合作的决策门槛
4. 即使不转化，我们也积累了行业知识

### Q4：这个方法需要多少人天？

**A**：
- 每周参会：2小时
- 会议整理分析：2小时
- 报告撰写：2小时
- 客户沟通：1小时
- **合计：每周7小时，4周共28小时**

按5000元计算，时薪约178元，是合理的。

### Q5：如何保护我们的方法不被竞品复制？

**A**：
1. **方法论壁垒**：竞品可以看到我们做什么，但不知道为什么这么做
2. **执行壁垒**：同样的方法，不同的人做效果不同
3. **数据壁垒**：我们积累的行业数据，竞品没有
4. **客户关系壁垒**：我们与客户建立了信任，竞品难切入
