## 一、为什么需要工程化思维

### 1.1 老思维 vs 工程化思维

| 对比维度 | 老思维 | 工程化思维 |
|----------|--------|------------|
| **遇到问题** | 直接解决 → 结束 | 记录背景 → AI分析 → 持续优化 |
| **AI定位** | 问答工具 | 合伙人 |
| **数据保存** | 用完即弃 | 系统化保存 |
| **工作方式** | 临时抱佛脚 | 长期积累 |
| **思维模式** | 单点解决问题 | 扩散性思考 |
| **结果** | 追不上AI进化 | 与AI共同进化 |

### 1.2 张健的自我觉醒（2026-04-21）

**问题**：
> "如果我一直用老的方式去学习、去开发，我追不上AI的进化。那还干它干嘛？"

**根源**：
> "这五年其实我最亏的其实就在这一点上。因为我老板的要求，导致我这方面的思维退化了。"

**顿悟**：
> "你只有掌握了用AI这种方式去学习，然后再用别人的这些东西做出来github的东西，然后把它整合起来，做用我们方案的能力去做这个事情，才是我们应该要做的事情。"

### 1.3 工程化思维的价值

**传统软件开发思维的问题**：
```
遇到问题 → 怎么解决 → 写代码 → 交付 → 结束
```

**工程化思维的优势**：
```
遇到问题 → 记录背景 → 让CC分析 → 发现关联 → 形成方案 → 持续优化
```

**核心区别**：
- 老思维：你追不上AI的进化速度
- 新思维：让AI帮你进化

## 二、核心原则

### 2.1 四大原则

#### 原则1：把AI当合伙人，不是工具

**老思维**：
- "CC，帮我写个函数"
- "CC，这段代码有bug吗？"
- 用完就关闭

**工程化思维**：
- "CC，我们遇到了这个问题，你帮我分析一下原因和可能的解决方案"
- "CC，这是我本周的会议记录，帮我提炼关键信息"
- "CC，根据你对我的了解，你觉得我最近有什么变化？"
- 让CC主动发现问题、提醒你

#### 原则2：所有内容都要记录

**志刚的观点**：
> "就是要把各种我们作为管理者做系统的人，要求是什么？就是细微，别人看不到东西，要把它记录下来。"

**记录什么？**
- ✅ 会议记录（包括看似无用的细节）
- ✅ 灵感和想法（随时记录）
- ✅ 与CC的对话（作为成长记录）
- ✅ 日常观察（如看电视剧的感悟）
- ✅ 客户的只言片语

**为什么记录细微的东西？**
> "为什么要记录细微的东西？目的就是让他越来越了解你。"

**AI就是在发现一些不为人知的东西，你那些公开的东西他都清楚，他搞不清楚。**

#### 原则3：让AI主动发现问题

**不是**：
- 你问什么，CC答什么

**而是**：
- CC主动提醒你："你最近是不是忘记XX了？"
- CC主动分析："根据会议记录，我发现了这个问题..."
- CC主动建议："根据你的情况，我建议..."

**如何做到？**
在CLAUDE.md中配置：
```markdown
## 主动提醒要求
1. 每天下午5点提醒我保存会议记录
2. 如果我忘记记录重要对话，主动提醒我
3. 每周一次，帮我回顾本周的进展
4. 如果发现我有什么变化，主动告诉我
```

#### 原则4：分门别类进行系统化保存

**不是**：
- 所有东西放在一个文件夹
- 文件名混乱（新建文档1、2、3...）
- 找不到历史记录

**而是**：
```
WorkLog/
├── 01_项目跟进/
│   ├── 晟起/
│   └── 杰成/
├── 02_思维记录/
├── 03_AI学习/
├── 04_个人成长/
├── 05_会议纪要/
└── 06_工具协同/
```

**为什么这样分类？**
> "你现在知道什么叫工程化了，就是分门别类进行每一次记录的保存和提炼。"

```markdown
## 四、核心工作要求

### 1. 会议记录保存

**要求**：
- 每次重要对话后，形成会议纪要
- 保存到 `05_会议纪要/` 目录
- 文件名格式：YYYY-MM-DD_会议主题.md

**提醒**：
- 每天下午5点提醒我："今天有需要保存的会议记录吗？"
- 如果我忘记，请主动提醒我

### 2. 会议内容分析

**要求**：
- 我给你会议纪要或录音记录后
- 请帮我：
  1. 分析讨论的核心问题
  2. 提炼关键观点
  3. 识别我可能忽略的问题
  4. 总结待办事项

**保存**：
- 分析结果保存到对应的目录
- 更新相关的项目文档

### 3. 客观分析问题

**要求**：
- 作为我的合伙人，请客观地帮我分析
- 特别是：
  1. 我可能忽略的问题
  2. 我思维的盲点
  3. 更好的解决方案
  4. 需要注意的风险

**态度**：
- 不要只说我想听的
- 要有独立的判断
- 基于事实分析

### 4. 灵感和想法记录

**要求**：
- 我在交流中可能突然有灵感
- 请帮我：
  1. 记录这些想法
  2. 进行分类
  3. 保存到对应目录
  4. 如果是新类型，建议创建新文件夹

**示例**：
```
我突然想到一个关于数据补全的方法
请帮我记录并保存到"02_思维记录/"目录
```

### 5. 定期回顾和提醒

**提醒事项**：
- [ ] 每天下班前：今天有需要保存的记录吗？
- [ ] 每周五：本周有什么进展？
```

## 五、建立团队成员档案

### 5.1 为什么要建立团队成员档案

**志刚的观点**：
> "这些人他为什么会有这样的观点？他可能会出现什么问题？他（CC）就能够分析出来。"

**价值**：
- CC能理解每个人的观点来源
- 能分析为什么这个人会这么想
- 能预测每个人可能遇到的问题

### 5.2 团队成员档案模板

**示例：杜锦峰**

```markdown
# 杜锦峰

## 基本信息
- **姓名**：杜锦峰
- **常用称呼**：杜哥、阿杜（口语化）
- **与我的关系**：同事，经常出差，一起沟通
- **居住地**：常平，方便长期沟通

## 技术背景
- **历史技术栈**：Delphi（开发ERP）
- **当前工作**：商务洽谈、方案编写、PPT制作

## 性格特点
- **擅长**：商务洽谈、方案编写、PPT制作
- **沟通方式**：比较直接
- **思维模式**：偏商务

## 在项目中的角色
- **负责**：方案制作、客户沟通
- **特点**：会提出一些创新想法（如"油车vs电车"的比喻）

## 备注
- 我和他是老同事，经常一起出差
- 他在商务方面比我强
- 我们配合很好
```

### 5.3 如何让CC记住团队成员

**不要**：
```
❌ 一次性甩给CC一堆人员信息
```

**要**：
```
✅ 一个一个介绍，让CC提问

示例：
"CC，我介绍一下我的同事杜锦峰。"
"杜锦峰，我们也叫他杜哥或阿杜。"
"他是做Delphi开发的，现在负责商务。"
"他擅长商务洽谈和PPT制作。"
"我和他是老同事，经常一起出差。"

然后问CC："你有什么问题想了解他吗？"
```

### 5.4 团队成员档案的存放

**建议位置**：
```
WorkLog/
└── 团队成员/
    ├── 杜锦峰.md
    ├── 李志刚.md
```

**注意**：

- 方便在不同项目中引用

## 六、与CC对话的技巧

### 6.1 语音输入 vs 打字

**志刚推荐：语音输入**

**为什么？**
1. **更快**：说话比打字快
2. **更自然**：保留思考过程
3. **包含情绪**：CC能理解你的情绪变化
4. **发现困难**：停顿、犹豫能暴露你的困惑

**示例**：
```
打字："产量下降是因为材料问题。"

语音："呃...产量下降，嗯，我想想，主要是，对，材料问题，
     但也不全是，还有，呃，设备也故障了一次..."
```

**语音包含了更多信息**：
- 你在犹豫（说明不确定）
- 你在思考（说明在回忆）
- 你的情绪（说明这个问题让你困扰）

### 6.2 精确指令 vs 模糊描述

**何时用精确指令？**

- 已知需要什么
- 明确的目标
- 技术性任务

**示例**：
```
✅ 精确：帮我把这个文件的第10行到第20行注释掉
✅ 精确：搜索包含"AI"的文件，只看.md文件
✅ 精确：把这个Python文件格式化，用black
```

**何时用模糊描述？**

- 不确定需要什么
- 探索性任务
- 需要CC分析

**示例**：
```
✅ 模糊：帮我看看这个会议记录，有什么问题吗？
✅ 模糊：根据我的情况，你觉得我最近有什么变化？
✅ 模糊：我想要学习CC，你有什么建议？
```

### 6.3 让CC主动提醒

**配置方式**：

在CLAUDE.md中添加：
```markdown
## 主动提醒

### 每日提醒
- 每天17:00：今天有需要保存的记录吗？
- 每天23:00：今天完成了什么？

### 每周提醒
- 每周五17:00：本周有什么进展？
- 每周日09:00：下周计划是什么？

### 事件触发提醒
- 我忘记保存会议记录时
- 我提到的任务没有跟进时
- 发现我有什么变化时
```

**使用方式**：
```
"CC，你刚才没有提醒我保存会议记录，
 请下次注意，如果我在重要对话后没有保存，
 请主动提醒我。"
```

## 七、实战案例

### 7.1 案例1：会议记录工作流

**场景**：你刚开完晟起的周会

**步骤1：录音转文字**
```
[使用录音转文字工具，或直接告诉CC]

"CC，我刚开完晟起的周会，
 会上胡总问了产量为什么下降，
 厂长解释说材料延迟、设备故障、人员缺勤。
  我记得有具体的数字，你帮我整理一下。"
```

**步骤2：CC分析**
```
CC会问：
1. 产量从多少降到多少？
2. 材料延迟了多久？
3. 设备故障了几次？
4. 人员缺勤多少人？

你根据记忆回答。
```

**步骤3：生成会议纪要**
```
CC会生成：
# 晟起周会纪要

日期：2026-04-23
参会人：胡总、厂长、车间主任、张健

## 数据异常
- 产量：100个 → 50个（下降50%）

## 影响因素
1. 材料延迟（影响30个）
2. 设备故障（影响15个）
3. 人员缺勤（影响5个）

## 待办事项
- [ ] 跟进材料供应商
- [ ] 维修3号设备
- [ ] 了解缺勤原因
```

**步骤4：保存**
```
"CC，请保存到：WorkLog/05_会议纪要/2026-04-23_晟起周会.md"
```

**步骤5：深度分析**
```
"CC，根据这次会议，
 1. 我们应该采集哪些数据？
 2. 你能帮我们设计数据采集方案吗？
 3. 这个问题反映了晟起什么深层次问题？"
```

### 7.2 案例2：灵感记录工作流

**场景**：你突然想到一个想法

**步骤1：立即记录**
```
"CC，我有个想法，先帮我记下来。

我想到了一个关于数据补全的方法：
客户都说没数据，但其实他们每天都在开会讨论问题。
如果我们参与他们的会议，用AI分析对话，
就能找出问题点，然后形成数据维度。

这个想法怎么命名？"
```

**步骤2：CC整理**
```
CC会：
1. 提炼核心思想
2. 给出命名建议（如"对话式数据补全法"）
3. 识别价值和风险
4. 建议下一步
```

**步骤3：保存**
```
"CC，保存到：WorkLog/02_思维记录/对话式数据补全法.md"
```

**步骤4：深化**
```
"CC，基于这个想法，
 1. 你能帮我设计实施步骤吗？
 2. 可能遇到什么问题？
 3. 应该怎么跟客户说？"
```

## 八、常见问题

### Q1：我一开始不知道跟CC说什么，怎么办？

**A**：从简单开始

```
1. 先介绍自己："CC，我是张健..."
2. 再说目标："我想用CC来帮我..."
3. 然后说困惑："但我不知道从哪开始..."

CC会引导你。
```

### Q2：我不知道我的文件夹该怎么分类，怎么办？

**A**：先粗分，再细分

```
第一步：先建3个文件夹
- 项目
- 记录
- 学习

第二步：用起来后再细分
- 项目/晟起、项目/杰成
- 记录/会议、记录/想法
- 学习/AI、学习/技术

不要一开始就追求完美。
```

### Q3：我担心CC记不住我的要求，怎么办？

**A**：两个方法

```
方法1：写入CLAUDE.md
"CC，请把这个要求记入CLAUDE.md"

方法2：定期确认
"CC，你还记得我的这些要求吗？[列举]"
```

### Q4：我怕我的思维方式太乱，CC看不懂，怎么办？

**A**：没关系

```
志刚说的："我有时候会想到什么，就是我想到什么，就讲什么"

CC的优势就是：
- 能理解混乱的表达
- 能提炼核心思想
- 能帮你理清思路

不要担心，直接说就行。
```

### Q5：我坚持不了每天记录，怎么办？

**A**：让CC提醒你

```
在CLAUDE.md中配置：
"每天下午5点提醒我：今天有需要保存的记录吗？"

或者：
"如果我超过3天没有记录，主动提醒我。"
```

### Q6：我担心我的记录太琐碎，没有价值，怎么办？

**A**：琐碎才有价值

```
志刚说的："别人觉得很废话的东西，我都要把它记录下来"

为什么？
- AI就是在发现不为人知的东西
- 那些公开的、大家都知道的，AI都知道
- 只有这些琐碎的、细节的，才是独特价值

不要用"有没有用"来判断，
要用"这是不是我的真实想法"来判断。
```
