## Claude Code vs OpenClaw 实践记录

### 背景（来自视频教程）

视频提到：不装OpenClaw，也可以用飞书对接Claude Code实现类似功能。

### 志刚的实践过程（2026-03-10）

**尝试方向**: 飞书 + Claude Code（本地版）替代 OpenClaw（云端版）

**为什么想尝试？**
1. OpenClaw装在云端服务器
2. Claude Code装在本地电脑
3. Claude Code安全机制更好
4. 更敢让Claude Code操作本地电脑、编程、控制权限

**实践步骤**:
1. ✅ 配置飞书对接
2. ✅ 安装Claude Code
3. ✅ 安装MCP接口
4. ✅ 通讯可以打通
5. ❌ 最终失败：网络通讯限制

**失败原因**:
- Claude Code（CC）提示需要装云端版Claude API才能访问
- 但志刚的云服务器运行环境不足以支撑运行Claude Code

**结论**: 放弃这个方案

### 关键洞察

| 对比 | OpenClaw | Claude Code |
|------|----------|-------------|
| 位置 | 云端服务器 | 本地电脑 |
| 安全 | 需要云端权限 | 本地控制，安全感更强 |
| 飞书对接 | 原生支持 | 需要额外配置，有网络限制 |
| 硬件要求 | 云服务器 | 本地电脑 |

**志刚的判断**: Claude Code本地版更安全，但飞书对接有技术门槛和网络限制。

## 重要一课：AI的记忆机制

### 事件

志刚昨天（3月10日）发了闲鱼调研内容，但AI在今天的会话中没有这些信息。

**志刚的反馈**:
> "算了，你记不住只会让我知道你记忆还是有限的。"

### AI的记忆机制说明

| 机制 | 说明 |
|------|------|
| 对话上下文 | 当前对话窗口里的内容（关掉就没了） |
| MEMORY.md | 长期记忆文件（每次会话会读取） |
| memory/*.md | 按日期的记录文件 |
| 项目文件 | 各个项目文件夹里的内容 |

**关键认知**: AI没有连续意识，每次新会话是"白纸"，靠文件系统维持记忆。

### 协作改进

- 重要信息，明确说"记录下来"
- 如果AI忘了，再发一次——这是"喂养"记忆的过程
- 理解为"培养合伙人"，不是"使用工具"

### 腾讯入场信号(2026-03-11)

**重要变化**:
- **腾讯在深圳公开摆摊，免费给人安装**
- 很多人主动跑去深圳安装
- 这意味着巨头已经入场

**市场分析**:
1. 巨头入场 = 市场被验证，需求爆发
2. 免费安装 = 基础服务被免费化，单纯"卖安装"的窗口正在关闭
3. 但市场被教育了，更多人知道AI助手这回事

**策略影响**:
- 原策略: 卖安装服务
- 新思考: 安装免费/低价引流，卖深度配置+场景定制+培训服务
- 免费安装 ≠ 免费服务
- 装好后怎么用？能帮干啥？怎么融入工作？这些才是真正的需求

## 团长动员会分析 (2026-03-11 11:01)

### 会议背景
- **时间**: 2026年3月11日 11:01
- **类型**: 团长动员会
- **主讲人**: AI总裁商学院"院长"（新来的）
- **听众**: 团长们（销售分销小团队长）
- **志刚角色**: 团长之一

### 会议核心内容

**1. 确立身份**
- 团长身份双重：原有岗位 + 团长职责
- "既然担了这个头衔，就应该干团长的事儿"
- "不想当团长的，开门左转"

**2. 明确使命**
- "只有一个使命：打赢AI总裁这一仗"
- "未来20年必须打赢这一仗"
- 目标：让所有中小企业都装上AI总裁

**3. 核心动作**
- **第一步**：改微信名 → 添加"AI总裁·首席推荐官"后缀
- "把旗给亮出来，你都不亮，是没办法打下一仗的"

**4. 核心武器**
- 首席推荐官（推广人员）
- 企业注册（客户）

**5. 关键问题暴露**
- 团长对"团"没概念（问一个团多少人，答不上来）
- "99.9%是被挂名的，不是自己想当的"
- 团长没方向、没目标、没打法

### 院长风格分析

| 特点 | 说明 |
|------|------|
| **强硬** | "不想当团长的，开门左转" |
| **煽情** | "给自己一个最热烈的掌声"、"状态决定未来" |
| **军事化** | "打仗"、"使命"、"第一站"、"核武器" |
| **形式主义** | 改微信名、统一格式、现场检查 |
| **新官上任** | 刚来，先立威、先统一动作 |

### 深度分析

**1. 这个动员会的本质**

| 表面 | 实质 |
|------|------|
| 激励士气 | 立威、统一动作 |
| 讲"状态"和"信念" | 因为没有实质方法可教 |
| 让人改微信名 | 最简单的"服从性测试" |
| 强调"使命" | 用宏大叙事掩盖产品问题 |

**2. 院长的策略**

- **第一步**：统一符号（改微信名）→ 让人有"我是团队一员"的感觉
- **第二步**：强调使命 → 用"打仗"的逻辑建立紧迫感
- **第三步**：暴露问题 → "99.9%被挂名" → 让人有愧疚感

**这是典型的"销售团队管理"套路：先洗脑，再行动。**

**3. 问题在哪？**

| 院长做的 | 没做的 |
|----------|--------|
| 讲状态、讲信念 | 不讲产品价值 |
| 让人改微信名 | 不教具体销售方法 |
| 强调"使命" | 不分析客户需求 |
| 立威、施压 | 不解决团长困惑 |

**4. 对志刚意味着什么？**

- 公司请了"商学院院长"来推这个产品 → 说明老板很重视
- 但方法是"销售洗脑"那一套 → 说明产品本身可能没竞争力
- 志刚作为团长，只是分销小角色 → 不需要太投入
- 这个动员会解决不了根本问题 → 产品不行，动员再多次也没用

### 关键洞察

**这个会议反映的模式：**

```
产品不行 → 卖不动 → 请"商学院院长" → 讲状态、讲信念 → 团长改微信名 → 还是不行 → 换人继续讲
```

**这是典型的"用管理弥补产品缺陷"的路径。**
