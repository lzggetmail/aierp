## 一、核心理念

### 什么是"真正的Multi-Agent"？

| 传统方式 | Multi-Agent方式 |
|----------|-----------------|
| 窗口式指导（零散提问） | 定义式协作（提前规划） |
| 一个AI干所有事 | 多个专业Agent各司其职 |
| 对话传递信息 | 文件传递信息 |
| 容易上下文溢出 | 文件解决上下文限制 |

**核心转变**：从"用AI"到"管理AI团队"

## 二、七步完整流程

### 步骤1：研究项目启动与目标设定

**目的**：明确研究主题、质量要求、价值定位

**操作要点**：
1. 明确研究主题（如"中美AI竞争态势研究"）
2. 设定质量要求：高质量信息来源、可查可验证
3. 明确研究价值：谁用？用来干嘛？

**关键提示词**：
```
请你作为这个项目的PM（项目经理），规划一下这个研究该怎么做。
你可以定义不同智能体的角色，规划整个工作流。
我的要求是：这项报告应该是高质量信息来源，可查可验证。
```

**避坑指南**：
- ❌ 研究再好没人用 = 白做
- ✅ 先想清楚：这个研究给谁看？解决什么问题？

---

### 步骤2：项目经理AI规划整体方案

**目的**：让AI作为项目经理，设计可执行的协作框架

**操作要点**：
1. 任命PM AI作为项目经理
2. 要求AI考虑：上下文窗口限制、agent间协作、文件管理
3. 多轮打磨确认最终方案

**关键提示词**：
```
你需要考虑：
1. 上下文窗口的限制
2. 不同agent之间的协作
3. 把过程中的文档写到本地文件中
4. 工作流的跟进机制
```

**输出成果**：
- 完整的协作方案文档
- 智能体配置清单
- 文件管理规范

---

### 步骤3：七智能体专业分工定义

**目的**：定义每个Agent的角色、身份、职责边界

**推荐配置（7个Agent）**：

| Agent名称 | 角色 | 职责 |
|-----------|------|------|
| infraAgent | 算力基础设施专家 | 研究芯片、数据中心、云计算 |
| industryAgent | 产业分析师 | 研究AI在各行业的应用 |
| talentAgent | 人力资源专家 | 研究AI人才分布、培养 |
| policyAgent | 政策研究员 | 研究AI相关政策法规 |
| investmentAgent | 投资分析师 | 研究AI投资动态 |
| techAgent | 技术专家 | 研究AI技术发展 |
| summaryAgent | 综合分析师 | 整合所有报告，输出结论 |

**操作要点**：
- 每个Agent有明确的职责边界
- 定义可调用的工具和资源
- 明确交付成果格式

---

### 步骤4：文件驱动协作机制设计

**目的**：解决上下文窗口限制，建立Agent间信息交互机制

**核心原则**：
- Agent间不直接对话，通过文件交换信息
- 文件命名标准化
- 实时更新工作进度

**文件体系设计**：

```
项目文件夹/
├── 00_工作流状态.md          # 任务进度追踪
├── 01_规划文档.md            # 整体方案
├── 02_Agent配置/
│   ├── infraAgent.md
│   ├── industryAgent.md
│   └── ...
├── 03_专题研究/
│   ├── 01_算力基础设施.md
│   ├── 02_产业应用.md
│   └── ...
├── 04_综合报告.md
└── 05_摘要.md
```

**关键提示词**：
```
请设计基于文件的协作机制：
1. agent间信息交互通过文件进行
2. 实时更新工作进度文件
3. 统一的文件命名规范
4. 设置质量检查点
```

---

### 步骤5：执行环境配置与启动

**目的**：配置CLI工具，加载规划文档，启动协作

**推荐工具**：
- Code Buddy CLI
- Claude Code

**操作步骤**：
```bash
# 1. 打开终端
# 2. 安装工具（选一个）
npm install -g @codebuddy/cli
# 或使用 Claude Code

# 3. 创建项目文件夹
mkdir research-project
cd research-project

# 4. 加载规划文档，启动协作
```

**避坑指南**：
- 非程序员也能操作，实际难度不高
- 提前准备好规划文档

---

### 步骤6：执行监控与质量把控

**目的**：监控执行过程，评估产出质量

**执行时间**：约2小时（复杂研究）

**质量评估维度**：
| 维度 | 标准 |
|------|------|
| 结构完整性 | 是否有专题研究+综合报告+摘要 |
| 信息密度 | 内容是否有深度、有价值 |
| 可验证性 | 信息来源是否标注明确 |
| 逻辑连贯性 | 论证是否充分、逻辑是否清晰 |

**操作要点**：
- 可同时用两种工具对比验证
- 人工阅读验证AI生成内容
- 检查信息来源可靠性

---

### 步骤7：经验沉淀与新项目复用

**目的**：总结经验，提升后续项目效率

**关键提示词**：
```
请总结刚才执行multi-agent研究时的经验：
1. 成功的关键因素
2. 遇到的挑战和解决方案
3. 可复制的操作步骤
4. 问题解决库
```

**输出成果**：
- 经验沉淀文档
- 可复用的Agent配置模板
- 优化后的工作流程

## 三、人的价值重定位

### AI时代人的核心价值

| AI能做的 | 人要做的 |
|----------|----------|
| 收集资料 | 判断选题价值 |
| 整理信息 | 决定研究方向 |
| 生成报告 | 评估应用价值 |
| 分析数据 | 提供一手信息 |

**关键洞察**：
> "人要往价值链上游走——选题为什么要做？能用来干嘛？"

### AI无法替代的

1. **选题判断** — 知道什么值得研究
2. **价值评估** — 判断研究结果有什么用
3. **一手信息** — 线下真实交流和实践经验
4. **审美判断** — 高质量信息的判断力
