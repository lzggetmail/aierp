## 法律要点

### 降薪

- 劳动合同法第35条：变更合同需双方协商一致，书面形式
- 签了调薪表 = 视为同意，难推翻
- 但赔偿基数可争取按12个月平均算

### 工资扣罚

- 《工资支付暂行规定》第16条：每月扣除不得超过20%
- 剩余部分不能低于当地最低工资标准

### 股东身份

- 劳动关系和股东身份是独立的
- 被裁不影响股权
- 但股权价值待评估

### 赔偿标准（法律规定）

| 情况 | 赔偿 | 说明 |
|------|------|------|
| 正常裁员（提前30天通知） | N | 不需要公司制度写，法律规定的 |
| 没有提前30天通知 | N+1 | 不需要公司制度写，法律规定的 |
| 违法解除 | 2N | 如公司用KPI辞退但制度无依据 |

### KPI辞退的合法性

如果公司想用"KPI不合格"辞退，需要：
1. 制度里有明确规定
2. 制度经过民主程序（员工代表大会等）
3. 已经公示或告知员工
4. 有合理的考核标准和程序

**目前情况**：志刚没找到"连续两个C辞退"的条款 → 公司难以此为由合法辞退

### 解决方案：轻量化 AI ERP

#### 1. 解绑数据库约束
- 解除字段约束：减少数据输入限制
- 放开表格约束：允许数据灵活

#### 2. 简化审批流程
- 以前：十级审批
- 现在：一层，最多两层
- 未来：Chat 方式，大模型处理审批

#### 3. 前端重新开发
- CS 架构 → Web 架构
- 客户端安装 → 浏览器直接访问

#### 4. AI 化
- Chat 审批：用对话方式完成审批
- AI 弥补：大模型处理数据不严谨问题
- 智能辅助：降低操作门槛

### 核心理念

| 理念 | 说明 |
|------|------|
| **轻量化设计** | 不追求大而全，追求小而美 |
| **先上马后优化** | 不是完美才上线，而是上线再优化 |
| **渐进式升级** | 朝着悟空的最终形态迈进 |
| **AI 弥补** | 用大模型能力弥补数据不严谨 |

### 核心公式

**轻量化 AI ERP = Web 前端 + 解绑数据库 + 简化流程 + AI 弥补**

### 与传统 ERP 对比

| 传统 ERP | 轻量化 AI ERP |
|----------|---------------|
| CS 架构 | Web 架构 |
| 十级审批 | 一两层审批 + Chat 审批 |
| 严格数据约束 | 解绑 + AI 弥补 |
| 重度流程控制 | 轻量流程 |
| 大而全 | 小而美 |
| 推行成本高 | 快速上手 |

### 演进路径

```
传统 ERP（CS + Delphi + 十级审批）
              ↓
        轻量化 AI ERP
              ↓
    Web 前端 + 解绑数据库 + 简化流程 + AI 弥补
              ↓
        朝着悟空的最终形态迈进
```

### 与"最小化验证"思维的关系

这个思路是"最小化验证"思维在 ERP 改良中的应用：
- 不追求完美（解绑、放宽）
- 快速验证（Web 前端、轻量化）
- 边走边调（渐进式升级）

## ERP AI 改良项目（与老同事合作）

### 项目背景

| 项目 | 说明 |
|------|------|
| **产品** | 老同事开发的 Delphi ERP（CS 架构） |
| **积累** | 十多年深耕，垂直领域（制造业）成熟 |
| **问题** | 太传统、太重、不适应未来趋势 |
| **目标** | AI 升级、适应 OPT（一人公司）趋势 |

### 核心定位：AI 顾问型 ERP

**不是 AI 助手，而是 AI 顾问**

| AI 助手 | AI 顾问 |
|---------|---------|
| 帮员工干活 | 帮老板发现问题 |
| 提高效率 | 降低风险、优化决策 |
| 客户觉得"省点事" | 客户觉得"值钱" |

**核心价值：让每个中小企业都拥有"全职 CFO + 运营顾问"**

### 设计架构：双端 + 双数据源 + AI 层

```
用户层：老客户用 Delphi，新客户用 Web + 飞书
    ↓
应用层：Web 端（规范性） + 飞书端（便捷性）
    ↓
AI 层：QClaw/QwClaw（数据分析、问题发现、建议生成）
    ↓
数据层：SQL Server（核心业务） + 飞书多维表格（汇总协作）
```

### Web 端职责

| 场景 | 说明 |
|------|------|
| 订单录入 | 严格字段约束、必填校验、数据格式化 |
| 库存管理 | 精确数量控制、批次管理、仓库区分 |
| 财务记账 | 借贷平衡、科目校验、凭证规范性 |
| 基础数据维护 | 客户档案、产品档案、供应商档案 |
| 复杂报表查询 | 多条件组合查询、数据导出、打印 |
| 系统配置 | 权限配置、流程配置、参数设置 |

### 飞书端职责

| 场景 | 说明 |
|------|------|
| AI Chat 查询 | 自然语言提问 |
| 汇总数据查看 | 老板看仪表盘、关键指标 |
| 任务管理 | 任务看板、日历视图 |
| 进度跟踪 | 生产进度、订单进度 |
| 考核分析 | 人员绩效、部门效率 |
| 移动端操作 | 外出时快速查询、审批 |
| 7×24 预警 | 异常自动推送、实时通知 |

### 数据分层设计

| 层 | 数据类型 | 数据量级 |
|------|---------|---------|
| **后端 SQL Server** | 核心业务数据 | 50 张表，百万级 |
| **前端飞书多维表格** | 汇总协作数据 | 20 张表，千级 |

### 数据同步策略

| 数据类型 | 同步方式 | 频率 |
|---------|---------|------|
| 基础数据 | 定时同步 | 每小时 |
| 业务数据 | 实时同步 | 立即 |
| 汇总数据 | 定时聚合 | 每天 |
| 任务数据 | 双向同步 | 实时 |
| 分析结果 | 单向写入 | 按需 |

### 核心公式

**AiERP = 老系统（不动） + Web 端（规范） + 飞书端（便捷） + AI 层（顾问） + 双数据源（分层）**

### MVP 验证计划

| 项目 | 说明 |
|------|------|
| **目标客户** | 朋友工厂，约 100 人 |
| **验证策略** | 部署现有 ERP + 同步开发 AI 功能前端 |
| **核心原则** | AI 可见、对比明显、快速见效 |

### 风险与建议

| 风险 | 应对 |
|------|------|
| 数据约束放宽 | 保留核心实体约束，放宽描述性字段 |
| AI 能力铺太开 | 先聚焦 1-2 个场景 |
| 技术选型 | 选成熟框架，避免过度工程化 |
