## 核心讨论内容

### 一、CC使用方法论（工程化思维）

#### 1.1 志刚的现有体系展示

**文件结构**：
```
WorkPlan/
├── 个人档案.md          # 团队成员背景、性格、能力
├── 客户档案/
│   ├── 晟起/
│   └── 杰成/
├── 会议纪要/            # 每次会议记录+AI分析
├── 待办.md              # 任务追踪
├── CLAUDE.md            # CC配置文件（操作习惯）
└── openclaw-config/     # 双AI协作配置
```

**核心原则**：
- **把AI当合伙人，不是工具**
- 所有内容都要记录（包括看似无用的细节）
- 让AI主动发现问题、提醒用户
- 分门别类进行系统化保存

#### 1.2 教学演示过程

**第一步：建立工作目录**
```
D:\WorkLog\  (张健的工作目录)
```

**第二步：创建CLAUDE.md配置文件**

核心配置内容：
```markdown
# CC工作指南

## 我的工作目录用途
- 项目跟进
- 思维记录
- AI学习
- 个人成长
- 会议纪要
- 工具协同

## 核心要求
1. 每天形成会议纪要并保存
2. 定期提醒我，防止遗忘
3. 对会议内容进行分析提炼后保存
4. 客观地帮我分析问题，特别是我忽略的问题
5. 根据我的新想法进行归类和新建文件
6. GitHub远程仓库定期同步（每天1-2次）
```

**第三步：建立团队成员档案**

关键点：
- 每个成员的背景、性格、特长
- 与"我"的关系
- 在项目中的角色
- 说话风格、俗称（如"杜哥"、"阿杜"都是指杜锦峰）

**为什么这么做？**
- AI能理解每个人的观点来源
- 能分析出为什么这个人会这么想
- 能预测每个人可能遇到的问题

#### 1.3 工程化思维的核心

**张健的痛点**：
- 习惯了"开发思维"：遇到问题→直接解决→结束
- 缺乏"扩散性思考"：问题本质是什么？为什么发生？还有哪些关联？
- **"用战术上的勤奋掩盖战略上的懒惰"**

**志刚的回应**：
> "你现在知道什么叫工程化了，就是分门别类进行每一次记录的保存和提炼。"

**对比**：
| 老思维 | 工程化思维 |
|--------|------------|
| 直接解决问题 | 记录问题背景、前因后果 |
| 用完后即弃 | 保存会议纪要+分析提炼 |
| AI是工具 | AI是合伙人 |
| 问答式使用 | 让AI主动发现问题 |

### 二、突发灵感：数据补全与AI推行试点方法论 ⭐

这是本次会议最大的创新点！在讨论过程中突然想到的解决方案。

#### 2.1 问题的提出

**背景**：
- 晟起等中小企业数据不齐全
- 老板："我没数据，你怎么做AI？"
- 传统思维：先要求客户完善数据→再上线系统

**张健的经验**：
> "我们老是找，有时候我们找人过来问，有很多东西他是回答不出来的。因为这个是很细的日常事务。"

#### 2.2 创新解决方案

**核心思想**：
> **"用对话式追问来补全数据，而不是等待数据完善"**

**具体流程**：

```
┌─────────────────────────────────────────────────────────┐
│ 第一阶段：数据异常发现                                    │
├─────────────────────────────────────────────────────────┤
│ 发现数据异常：昨天100个，今天50个？                        │
│ → 为什么少了50个？                                        │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────┐
│ 第二阶段：对话式追问（录音记录）                           │
├─────────────────────────────────────────────────────────┤
│ 场景：参加客户周会/现场会议                                │
│ 方式：拍视频或录音                                        │
│ 提问示例：                                                │
│ - "今天为什么产量下降？"                                   │
│ - "材料不够？停电了？还是人员问题？"                        │
│ - 具体的数值是多少？                                       │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────┐
│ 第三阶段：AI分析整理                                      │
├─────────────────────────────────────────────────────────┤
│ 录音文件 → CC分析 → 提炼问题点                            │
│                                                         │
│ 识别影响因素：                                             │
│ - 材料供应问题                                            │
│ - 设备故障                                                │
│ - 人员缺勤                                                │
│ - 订单变化                                                │
│ ...                                                     │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────┐
│ 第四阶段：形成数据字段/维度                               │
├─────────────────────────────────────────────────────────┤
│ 从对话中集中化出关键维度：                                  │
│                                                         │
│ 影响产量的因素：                                           │
│ 1. 材料到货时间                                           │
│ 2. 设备稼动率                                             │
│ 3. 实际出勤人数                                           │
│ 4. 紧急插单数量                                           │
│ ...                                                     │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────┐
│ 第五阶段：设计数据补全方案                                │
├─────────────────────────────────────────────────────────┤
│ 针对每个维度设计：                                         │
│ - 采集方式（自动/手动）                                    │
│ - 采集频率                                                │
│ - 责任人                                                  │
│ - 校验逻辑                                                │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────┐
│ 第六阶段：持续跟踪与AI判断                                │
├─────────────────────────────────────────────────────────┤
│ 日常数据录入 → AI监控异常 → 自动追问 → 持续优化           │
└─────────────────────────────────────────────────────────┘
```

#### 2.3 关键创新点

**1. 逆向思维**
```
传统方式：数据完善 → 上系统 → AI分析
创新方式：AI参与 → 对话补全 → 形成数据 → 持续优化
```

**2. 最小化产品试点**
```
成本：5000-10000元
周期：2-4周
服务：
- 参与所有会议（录音/录像）
- 提供数据分析报告
- 形成数据补全方案
- AI辅助决策建议

目标：建立信心，证明价值
```

**3. 可复制的方法论**
- 问题询问技巧（形成skill）
- 数据维度识别能力
- AI分析模板

**张健的反馈**：
> "这个方式就是可以真的是到现场去做这个事情的时候，你要用这个方法论去参与客户的会议，现在记录你才能真正的袭击他核心核心的问题。"

#### 2.4 实施建议

**对晟起的下一步**：
1. 提出试点方案：5000-10000元
2. 参与每周例会（录音）
3. 每次会议后提供分析报告
4. 逐步形成数据字段
5. 设计数据采集方案
6. 建立持续监控机制

**成功关键**：
- ✅ 不等待数据完善
- ✅ 用对话代替表格
- ✅ AI辅助发现问题
- ✅ 逐步形成标准
- ✅ 快速建立信心

### 三、重要观点摘录

#### 3.1 关于AI使用

**志刚**：
> "你要理解AI是干什么的。AI就是在发现一些不为人知的东西，你那些公开的东西他都清楚，他搞不清楚。"

> "为什么要记录细微的东西？目的就是让他越来越了解你。"

**张健**：
> "我现在用他的还是用他的什么呢？就是他的知识就问你们应该是知识还是最最基础最弱部门的，还不算，因为为什么呢？因为他的平时用的都很好，还是很入门的，就跟普通用户没什么区别。"

> "因为我们如果还是用原来的一个思维不断的去开发去做，你用什么技术？你追不上他的进化。"

#### 3.2 关于思维转变

**张健的自我反思**：
> "我应该这么说，就是不光是我其实他们两个也是一样的。是的，不光是我，其实只是我的...因为他们在这个过程中间还是针对我是要去我要去开发。其实这里有个核心问题是什么呢？他们想的还是以工具化的形式去做这些事情。"

> "就是我因为如果你一直还是用老的方式去学习、去开发的话，你追不上他的进化。"

> "这五年其实我最亏的其实就在这一点上。因为我老板的要求，导致我这方面的思维退化了，这个方面的能力退化了。"

#### 3.3 关于记录细节

**志刚**：
> "就是要把各种我们作为管理者做系统的人，要求是什么？就是细微，别人看不到东西，要把它记录下来。"

> "以前就是太细了，我觉得这个戏要有什么用，好像没什么意义。因为这个都是日常琐碎的那你。"

> "这个哪里优势在于就是说很细枝末节。很细碎的东西，你能提炼出来它的关联性。"
