### 核心内容（发言人1分享）

**AI助手的协作流程**：
```
录音/会议/想法 → 文字转给大模型 → AI分析 → 存入记忆 → 持续提醒
```

**AI的三大价值**：
1. **分析** - 从杂乱信息中提取任务、好点子
2. **记忆** - 形成记录，有连贯性（知道昨天开车，今天开展会）
3. **提醒** - 用人性化的方式提醒执行，越来越懂你

**实际应用场景**：
- 开会时老板交代的事情
- 聊天时的好点子
- 任务拆解
- 情况变化时提醒调整

**金句**：
> "他会用人性的方法来提醒你，多注意执行的效果，他会越来越聪明，知道吧？他越来越理解你"

## 双 AI 合伙人架构（2026-03-15 20:03）

### 志刚的创新思维

> "在具体的工程管理及代码编程方式，使用 Claude Code，因为它更安全、稳定。但它不能手机端及随时沟通。采用 OpenClaw 作为 24×7 的任务助手与 AI 合伙人。让 CC 做好的项目文件或 Agent 代码，迁移到服务器中，与 OpenClaw 配合，形成资料参考或迁移成可用的 Agent。"

### 核心理念

**CC（工程合伙人）+ OpenClaw（全天候合伙人）各司其职**

### 角色定位

| 角色 | 工具 | 优势 | 局限 |
|------|------|------|------|
| **CC** | Claude Code | 稳定、安全、代码强 | 无手机端 |
| **龙虾** | OpenClaw | 24×7、手机端、飞书 | 工程能力不如 CC |

### 协作流程

```
CC 开发代码 → GitHub → OpenClaw 运行
OpenClaw 记录知识 → GitHub → CC 获取需求
```

### 目标

形成全天候、全成员的 AI 团队（类似李一舟的设计理念）
