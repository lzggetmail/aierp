# 文件和文件夹命名规范

> **目的**：建立统一的命名体系，提高文件可识别性和可检索性
> **原则**：清晰、一致、可排序
> **语言**：中文为主，英文标签和代码为辅

## 📁 文件夹命名规范

### 数字前缀体系

使用数字前缀实现文件夹排序和分类：

```
00_收件箱        - 快速捕获的临时内容
10_日记          - 时间顺序的记录
20_项目          - 以项目为单位的内容
30_领域          - 持续关注的领域
40_资源          - 可复用的资源库
50_归档          - 不常用但需保留的内容
```

### 命名格式

#### 格式
```
编号_主题名称
```

#### 规则
- ✅ 使用两位数字（00-99）
- ✅ 数字后跟下划线
- ✅ 使用中文主题名
- ✅ 主题名清晰明确
- ❌ 不使用特殊字符（除了连字符-）
- ❌ 不使用空格

### 示例

#### ✅ 好的命名
```
00_收件箱
10_日记
20_项目
20_项目-ai-agent
35_知识管理
40_工具资源
```

#### ❌ 不好的命名
```
Inbox
日记
Projects
AI Agent开发
knowledge-management
```

## 📄 笔记文件命名规范

### 基本格式

```
[类型前缀]-主题名称.md
```

### 类型前缀体系

| 前缀 | 用途 | 示例 |
|------|------|------|
| `MOC-` | 知识地图 | `MOC-AI开发知识地图.md` |
| `模板-` | 模板文件 | `模板-Agent开发笔记.md` |
| `案例-` | 案例研究 | `案例-XX项目实现.md` |
| `SOP-` | 流程文档 | `SOP-Agent开发流程.md` |
| `问题-` | 问题记录 | `问题-工具调用失败.md` |
| `资源-` | 资源收集 | `资源-Claude官方文档.md` |
| `方法-` | 方法论 | `方法-费曼学习法.md` |
| (无前缀) | 普通笔记 | `Agent定义.md` |

### 命名原则

#### 1. 清晰性
文件名应该能反映文件内容

#### ✅ 好的命名
```
Agent设计模式.md
费曼学习法详解.md
Obsidian高级技巧.md
```

#### ❌ 不好的命名
```
想法.md
笔记.md
内容.md
临时.md
```

#### 2. 可搜索性
使用可能搜索到的关键词

#### ✅ 好的命名
```
Claude Code配置指南.md
Prompt优化技巧.md
知识库架构设计.md
```

#### ❌ 不好的命名
```
配置.md
技巧.md
设计.md
```

#### 3. 一致性
同类文件使用一致的命名模式

#### ✅ 一致的命名
```
Agent开发SOP.md
测试流程SOP.md
部署流程SOP.md
```

#### ❌ 不一致的命名
```
Agent开发SOP.md
测试流程.md
如何部署.md
```

### 特殊情况处理

#### 1. 日期笔记
格式：`YYYY-MM-DD-主题.md`

示例：
```
2026-03-25-日记.md
2026-03-25-学习记录.md
2026-03-25-项目复盘.md
```

#### 2. 序列笔记
格式：`主题-序号.md`

示例：
```
费曼学习法-01原理.md
费曼学习法-02实践.md
费曼学习法-03案例.md
```

#### 3. 临时笔记
使用临时前缀，后续整理时重命名：

```
临时-想法.md
待整理-摘录.md
```

## 🔗 双链命名建议

### 文件内链接格式

在Markdown中使用双链时：
```markdown
[[文件名]]           # 完整文件名
[[文件名|显示文本]]  # 自定义显示文本
```

### 链接命名建议

#### 1. 直接使用文件名
```markdown
我正在学习 [[费曼学习法]]。
参考 [[Agent开发SOP]]。
```

#### 2. 自定义显示文本
```markdown
使用 [这个技巧](文件名) 来提高效率。
详见 [官方文档](资源-Claude官方文档)。
```

#### 3. 链接到标题
```markdown
查看 [[费曼学习法#四个步骤]]。
参考 [[Agent开发SOP#设计阶段]]。
```

## 📂 项目文件夹组织

### 标准项目结构

```
项目名称/
├── 00_项目概况.md          # 项目概述
├── 01_需求分析/
│   ├── 需求文档.md
│   └── 用户故事.md
├── 02_设计文档/
│   ├── 架构设计.md
│   └── 接口设计.md
├── 03_开发记录/
│   ├── 2026-03-25-实现功能A.md
│   └── 2026-03-26-修复BugB.md
├── 04_测试文档/
│   ├── 测试计划.md
│   └── 测试报告.md
├── 05_部署文档/
│   └── 部署指南.md
└── 06_项目总结/
    └── 项目复盘.md
```

### 项目命名

格式：`项目-主题-状态`

示例：
```
项目-AI Agent开发-进行中
项目-知识库搭建-已完成
项目-自动化测试-计划中
```

## 🔍 搜索优化

### 文件名包含关键词

确保文件名包含可能搜索的关键词：

#### ✅ 好的示例
```
Claude Code API调用方法.md
Obsidian插件开发完整指南.md
费曼学习法的四个步骤.md
```

这些文件名可以通过多种方式搜到：
- "Claude" "Code" "API"
- "Obsidian" "插件" "开发"
- "费曼" "学习法" "步骤"

#### ❌ 不好的示例
```
配置.md
指南.md
方法.md
```

### 使用别名

对于常用概念的别名，可以在文件开头添加：

```markdown
---
别名: [Agent, 智能体, AI代理]
---

# Agent定义
```

## 📝 实践建议

### 创建文件时

1. **先思考**：这个文件是什么类型？
2. **选前缀**：根据类型选择前缀
3. **定名称**：使用清晰、可搜索的名称
4. **查重复**：检查是否已有类似文件

### 重命名文件时

1. **更新链接**：检查哪些文件链接了它
2. **批量更新**：使用工具更新所有链接
3. **更新MOC**：更新相关的MOC文档

### 整理文件时

1. **统一命名**：将不一致的命名统一
2. **移动位置**：移动到合适的文件夹
3. **更新索引**：更新所有相关索引
