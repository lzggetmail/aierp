# AiERP 数据权限隔离设计方案

> 日期：2026-03-18
> 目标：实现多层级的数据权限控制，确保不同角色只能访问授权的数据

---

## 一、需求概述

### 1.1 核心问题

在企业 ERP 系统中，**不是所有数据都可以给所有人看到**。不同角色需要访问不同的数据，敏感数据需要严格保护。

### 1.2 权限隔离的三个层面

| 层面 | 问题 | 风险 |
|-----|------|------|
| **多租户隔离** | 客户 A 的数据会不会被客户 B 看到？ | 商机泄露、数据混乱 |
| **用户权限隔离** | 普通员工能不能看到财务数据？ | 薪资泄露、客户流失 |
| **敏感数据隔离** | 哪些数据可以放飞书？ | 商业机密泄露、合规问题 |

---

## 二、多租户隔离方案

### 2.1 推荐方案：每个客户使用自己的飞书企业

```
客户 A 使用自己的飞书企业
    └── 你们的 AI 应用通过飞书 ISV 接入

客户 B 使用自己的飞书企业
    └── 你们的 AI 应用通过飞书 ISV 接入
```

**实现方式**：
- 开发飞书 ISV 应用
- 客户在自己的飞书企业中安装应用
- 每个客户的数据存储在自己的飞书企业中

**优势**：
- ✅ 天然的多租户隔离
- ✅ 数据完全独立
- ✅ 客户更放心（数据在自己手里）

---

### 2.2 备选方案：单飞书企业 + 多空间

```
一个飞书企业（你们的公司）
    ├── 客户 A 的多维表格空间
    ├── 客户 B 的多维表格空间
    └── 客户 C 的多维表格空间
```

**适用场景**：初期试点阶段

### 4.1 按数据表分类的权限

| 数据表 | 老板 | 财务主管 | 销售 | 销售主管 | 仓管 | 生产主管 |

| 员工表 | 全部 | 全部 | 无 | 无 | 无 | 无 |

| 订单表 | 全部 | 全部 | 自己的 | 全部 | 无 | 无 |

| 订单利润 | 全部 | 全部 | ❌ | ❌ | ❌ | ❌ |
| 库存表 | 全部 | 查看 | 查看 | 查看 | 编辑 | 查看 |
| 库存成本 | 全部 | 全部 | ❌ | ❌ | ❌ | ❌ |
| 财务凭证 | 全部 | 全部 | ❌ | ❌ | ❌ | ❌ |

| 销售统计 | 全部 | 全部 | 自己的 | 全部 | 无 | 无 |
| 财务月报 | 全部 | 全部 | ❌ | 部分 | ❌ | ❌ |
| 生产进度 | 全部 | ❌ | ❌ | ❌ | ❌ | 全部 |
| **任务数据** |
| 待办任务 | 全部 | ❌ | 自己的 | 全部 | 自己的 | 全部 |

**图例**：
- **全部**：可以查看所有数据

## 五、数据分类与隔离策略

### 5.1 数据分类存储规则

| 数据类型 | 存储位置 | 飞书访问 | 原因 |
|---------|---------|---------|------|
| **财务凭证** | SQL Server | ❌ | 敏感，不能泄露 |
| **员工薪资** | SQL Server | ❌ | 隐私数据 |
| **成本信息** | SQL Server | ❌ | 商业机密 |
| **客户完整信息** | SQL Server | ❌ | 客户资源 |
| **订单明细** | SQL Server | ❌ | 核心业务 |
| **财务月报** | SQL Server + 飞书 | ✅ 脱敏后 | 管理需要 |
| **销售统计** | SQL Server + 飞书 | ✅ 脱敏后 | 业务分析 |
| **产品目录** | SQL Server + 飞书 | ✅ 公开信息 | 便于查询 |
| **任务看板** | 飞书 | ✅ | 协作需要 |
| **AI 分析报告** | 飞书 | ✅ | 价值呈现 |

### 5.2 核心原则

```
🔴 绝不放飞书（只存在 SQL Server）：
├── 财务凭证和明细
├── 员工薪资
├── 核心配方/工艺
├── 供应商秘密协议
└── 其他商业机密

🟡 可以放飞书，但需要权限控制：
├── 汇总财务数据（如月报）
├── 销售统计（脱敏后）
├── 生产进度（不含核心工艺）
└── 任务分配

🟢 可以放飞书：
├── 公开的产品信息
├── 公开的客户信息（脱敏）
├── 任务看板
└── AI 分析报告（不含敏感数据）
```

## 六、技术实现方案

### 6.1 权限控制层次

```
┌─────────────────────────────────────────────────────────┐
│                  权限控制层次                             │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  第一层：飞书多维表格权限                                │
│  ├── 表格级别：谁能访问哪个表                            │
│  ├── 视图级别：不同角色看不同视图                        │
│  ├── 字段级别：哪些字段可见                              │
│  └── 记录级别：只能看到自己的记录                        │
│                                                          │
│  第二层：API 层权限控制                                  │
│  ├── 角色验证：检查用户角色                              │
│  ├── 操作验证：检查是否有执行该操作的权限                │
│  ├── 行级过滤：添加 WHERE 条件                           │
│  ├── 字段过滤：排除敏感字段                              │
│  └── 数据脱敏：对敏感数据进行脱敏处理                    │
│                                                          │
│  第三层：SQL Server 权限控制                             │
│  ├── 数据库用户：每个角色对应不同的数据库用户            │
│  ├── 表级权限：GRANT/REVOKE                             │
│  ├── 行级安全：Row-Level Security (RLS)                 │
│  └── 视图：创建不同的视图给不同角色                      │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 6.2 SQL Server 权限控制

#### 创建角色和用户

```sql
-- 1. 创建角色
CREATE ROLE role_boss;
CREATE ROLE role_finance_manager;
CREATE ROLE role_sales;
CREATE ROLE role_sales_manager;
CREATE ROLE role_warehouse;
CREATE ROLE role_production_manager;

-- 2. 创建用户并分配角色
CREATE USER user_boss FOR LOGIN boss_login;
ALTER ROLE role_boss ADD MEMBER user_boss;

CREATE USER user_sales_001 FOR LOGIN sales_001_login;
ALTER ROLE role_sales ADD MEMBER user_sales_001;
```

#### 表级权限控制

```sql
-- 老板：所有权限
GRANT SELECT, INSERT, UPDATE, DELETE ON orders TO role_boss;
GRANT SELECT, INSERT, UPDATE, DELETE ON customers TO role_boss;
GRANT SELECT ON financial_vouchers TO role_boss;

-- 仓管：看不到订单，只能看到库存
DENY SELECT ON orders TO role_warehouse;
GRANT SELECT, UPDATE ON inventory TO role_warehouse;
```

#### 行级安全（Row-Level Security）

```sql
-- 启用行级安全
ALTER TABLE orders ENABLE SECURITY POLICY;

-- 创建安全策略
CREATE SECURITY POLICY orders_security_policy
ADD FILTER PREDICATE fn_security_predicate_user_id(sales_person_id)
ON orders;

-- 只有销售和管理员能看到所有数据
-- 销售只能看到自己的订单
```

#### 使用视图控制权限

```sql
-- 销售：只能看到自己的订单
CREATE VIEW view_sales_my_orders AS
SELECT
    order_id,
    order_code,
    customer_id,
    order_date,
    total_amount,  -- 能看到金额
    status
    -- 不包含 cost 和 profit
FROM orders
WHERE sales_person_id = USER_ID();

GRANT SELECT ON view_sales_my_orders TO role_sales;

-- 财务主管：可以看到所有订单，但看不到成本和利润
CREATE VIEW view_finance_orders AS
SELECT
    order_id,
    order_code,
    customer_id,
    order_date,
    total_amount,
    status
FROM orders;

GRANT SELECT ON view_finance_orders TO role_finance_manager;
```

### 6.3 飞书多维表格权限控制

#### 表格级别权限

```javascript
const tablePermissions = {
  // 财务数据表：只有财务主管和老板能看
  '财务月报表': {
    viewers: ['财务主管', '老板'],
    editors: ['财务主管']
  },

  // 销售数据表：销售只能看自己的
  '订单跟进表': {
    viewers: ['销售', '销售主管', '老板'],
    editors: ['销售', '销售主管'],
    row_filter: 'creator == current_user'
  },

  // 任务表：所有人都能看，但只能编辑自己的
  '待办任务表': {
    viewers: ['所有员工'],
    editors: ['任务负责人']
  },

  // 产品表：所有人都能看
  '产品目录表': {
    viewers: ['所有员工'],
    editors: ['仓管', '生产主管']
  }
};
```

#### 字段级别权限

```javascript
const fieldPermissions = {
  '订单表': {
    // 所有角色都能看到基础字段
    common_fields: ['订单编号', '订单日期', '客户名称', '产品名称', '数量'],

    // 只有特定角色能看到敏感字段
    sensitive_fields: {
      '售价': ['销售', '销售主管', '老板', '财务主管'],
      '成本价': ['老板', '财务主管'],
      '利润': ['老板', '财务主管']
    }
  }
};
```

#### 视图级别权限

```javascript
const viewPermissions = {
  // 老板视图：看所有数据
  '老板视图': {
    audience: ['老板'],
    filters: {}
  },

  // 销售视图：只看自己的数据
  '销售视图': {
    audience: ['销售'],
    filters: {
      sales_person_id: '当前用户'
    }
  },

  // 仓管视图：只看待发货的订单
  '仓管视图': {
    audience: ['仓管'],
    filters: {
      status: '待发货'
    },
    hide_fields: ['售价', '成本价', '利润']
  }
};
```

### 6.4 API 层权限控制

#### 权限配置

```javascript
const permission = {
  roles: {
    BOSS: 'boss',
    FINANCE_MANAGER: 'finance_manager',
    SALES: 'sales',
    SALES_MANAGER: 'sales_manager',
    WAREHOUSE: 'warehouse',
    PRODUCTION_MANAGER: 'production_manager'
  },

  tablePermissions: {
    orders: {
      boss: {
        action: ['read', 'create', 'update', 'delete'],
        rowFilter: null,
        fields: null
      },
      finance_manager: {
        action: ['read'],
        rowFilter: null,
        fields: {
          exclude: ['cost', 'profit']
        }
      },
      sales: {
        action: ['read', 'create', 'update'],
        rowFilter: 'sales_person_id = current_user_id',
        fields: {
          exclude: ['cost', 'profit']
        }
      },
      warehouse: {
        action: [],
        rowFilter: null,
        fields: null
      }
    }
  }
};
```

#### 权限检查中间件

```javascript
function checkPermission(tableName, action) {
  return async (req, res, next) => {
    const userRole = req.user.role;
    const userId = req.user.id;

    // 1. 检查角色是否有访问该表的权限
    const tablePerm = permission.tablePermissions[tableName]?.[userRole];

    if (!tablePerm) {
      return res.status(403).json({ error: '无权访问该资源' });
    }

    // 2. 检查是否有执行该操作的权限
    if (!tablePerm.action.includes(action)) {
      return res.status(403).json({ error: '无权执行该操作' });
    }

    // 3. 添加行级过滤
    if (action === 'read' && tablePerm.rowFilter) {
      req.rowFilter = tablePerm.rowFilter.replace('current_user_id', userId);
    }

    // 4. 添加字段过滤
    if (action === 'read' && tablePerm.fields) {
      req.fieldFilter = tablePerm.fields;
    }

    next();
  };
}
```

### 6.5 数据脱敏

#### 脱敏规则

```javascript
class DataAnonymizer {
  rules = {
    customer: {
      contact: (value) => {
        // 联系人脱敏：张三 → 张**
        if (!value || value.length <= 1) return value;
        return value[0] + '*'.repeat(value.length - 1);
      },
      phone: (value) => {
        // 手机号脱敏：13812345678 → 138****5678
        if (!value || value.length !== 11) return value;
        return value.replace(/(\d{3})\d{4}(\d{4})/, '$1****$2');
      },
      address: (value) => {
        // 地址脱敏：保留到区级
        if (!value) return value;
        const parts = value.split(/(省|市|区|县)/);
        if (parts.length >= 4) {
          return parts.slice(0, 4).join('');
        }
        return value;
      }
    },

    order: {
      cost: (value) => '***',
      profit: (value) => '***'
    },

    employee: {
      salary: (value) => '***',
      idCard: (value) => {
        // 身份证：脱敏
        if (!value || value.length !== 18) return value;
        return value.replace(/(\d{6})\d{8}(\d{4})/, '$1********$2');
      }
    }
  };

  anonymize(data, category, userRole) {
    const rules = this.rules[category];
    if (!rules) return data;

    const result = {};

    for (const [field, value] of Object.entries(data)) {
      const rule = rules[field];
      if (rule) {
        result[field] = rule(value, userRole);
      } else {
        result[field] = value;
      }
    }

    return result;
  }
}
```

## 七、实施计划

### 7.1 分阶段实施

```
第一阶段（MVP）：
├── 实现 API 层权限控制
├── 实现基本的数据脱敏
└── 使用飞书原生权限设置

第二阶段：
├── 完善 SQL Server 权限控制
├── 实现行级安全（RLS）
└── 完善字段级权限

第三阶段：
├── 实现审计日志
├── 实现权限管理后台
└── 定期权限审计
```

### 7.2 核心原则

1. **最小权限原则**：每个角色只能看到必要的数据
2. **多层防护**：飞书 + API + SQL Server 三层控制
3. **敏感数据保护**：成本、利润、薪资等敏感数据严格控制
4. **数据脱敏**：即使有权限，也要对敏感字段进行脱敏处理
